# AI Ensemble Workflow for Life-Logging Ledger

## 1. 목표
이 문서는 `Claude Pro`, `ChatGPT Plus + Codex CLI/앱`, `Google AI Pro + Gemini CLI`를 동시에 운용해, 기획부터 MVP 구현까지 병렬 처리 효율을 최대화하는 운영 방식을 정리한다.

핵심 원칙은 다음 세 가지다.

1. 하나의 AI에 모든 역할을 몰지 않는다.
2. 각 도구는 "잘하는 일"만 맡긴다.
3. 산출물은 반드시 하나의 저장소와 하나의 이슈 보드로 수렴시킨다.

---

## 2. 권장 역할 분담

### Gemini AI Pro + Gemini CLI
가장 먼저 붙여야 하는 역할은 `대용량 문맥 정리`와 `리서치형 설계`다.

권장 담당:
- PRD 확장
- 시장/유스케이스/경쟁 구조 정리
- 도메인 모델 초안
- DB 스키마 초안
- 정책 문서 초안
- 블록체인 없이도 성립하는 제품 코어 정리

이유:
- 긴 컨텍스트를 한 번에 정리하고 구조화하는 데 유리하다.
- Gemini CLI는 터미널 기반이라 문서 초안과 구조 설계 산출물을 파일로 빠르게 고정하기 좋다.

주의:
- 구현 세부 정확성은 반드시 다른 코딩 에이전트가 재검토한다.

---

### Claude Pro
`화면 설계`, `카피`, `사용자 경험`, `정보 구조`, `프로토타입 표현력`에 집중시키는 편이 효율적이다.

권장 담당:
- 사용자 플로우 설계
- 와이어프레임 설명
- 랜딩 페이지 카피
- 앱 내 정보 구조
- 감성 중심 UX 문구
- 프론트엔드 컴포넌트 스펙
- 디자인 QA 체크리스트

이유:
- 프론트엔드 구조 제안과 UI 서술, 화면 수준의 일관성 설계가 강하다.
- 화면별 요구사항을 자연어로 정리해 주면 이후 Codex가 구현하기 쉬워진다.

주의:
- 실제 코드베이스 반영과 테스트까지 맡기기보다, 화면 스펙과 상호작용 정의까지 맡기는 편이 안정적이다.

---

### ChatGPT Plus + Codex CLI
`로컬 코드베이스에서 직접 수정하고 검증하는 실행 담당`으로 두는 것이 가장 효율적이다.

권장 담당:
- Next.js 구조 생성 및 정리
- Supabase 연동 코드
- API route 구현
- 인증 흐름 구현
- 파일 업로드 파이프라인
- 테스트 실행 및 수정
- 리팩터링
- 문서화된 스펙의 실제 코드 반영

이유:
- 로컬 저장소를 직접 읽고 수정하고 명령을 실행하는 루프에 강하다.
- CLI는 빠른 구현, 버그 수정, 테스트 중심 반복에 적합하다.

주의:
- 기획이 흔들리는 상태에서 바로 코딩에 투입하면 재작업이 커진다.
- 따라서 Codex CLI는 "정리된 이슈"를 받아 처리하는 구조가 좋다.

---

### ChatGPT Plus + Codex 네이티브 앱
`멀티 에이전트 조정`, `병렬 작업`, `검토`, `문서/코드 허브` 역할로 쓰는 편이 좋다.

권장 담당:
- 여러 작업 브랜치 병렬 진행
- 코드리뷰
- 스펙 문서와 구현 상태 연결
- 자동화 작업 설정
- 반복 QA/체크리스트 자동 실행
- 디자인 파일, 문서, 이슈, 코드 작업의 허브 역할

이유:
- OpenAI 공식 안내 기준으로 Codex 앱은 여러 에이전트를 병렬로 돌리고, worktree와 automations를 활용하는 데 강점이 있다.
- CLI보다 작업 orchestration에 유리하다.

주의:
- 앱은 조정 허브로 쓰고, 세밀한 구현은 CLI나 실제 IDE에서 마무리하는 편이 빠르다.

## 4. 가장 효율적인 운영 구조

### A. 산출물 흐름
권장 흐름은 아래와 같다.

1. Gemini가 긴 기획을 구조화한다.
2. Claude가 사용자 경험과 화면 스펙으로 바꾼다.
3. Codex가 이슈 단위로 구현한다.
4. Codex 앱이 병렬 작업과 검토를 조정한다.
5. 최종 검수는 사람이 제품 방향과 위험을 판단한다.

즉, `Gemini = 구조화`, `Claude = 경험 설계`, `Codex = 실행`, `사람 = 우선순위와 책임` 구조가 가장 안정적이다.

---

### B. 브랜치 전략
브랜치를 AI별이 아니라 기능별로 나눈다.

예시:
- `feat/auth-onboarding`
- `feat/playlist-capture-flow`
- `feat/proof-ingestion-pipeline`
- `feat/marketplace-mvp`
- `feat/admin-dataset-export`

이유:
- AI별 브랜치 전략은 충돌과 책임 불명확성을 만든다.
- 기능 브랜치가 병렬성과 검수성을 모두 높인다.

---

### C. 이슈 단위 분해
한 이슈는 다음 조건을 만족해야 한다.

- 1~3시간 내 구현 가능
- 입력/출력이 명확함
- 완료 조건이 테스트 가능함
- 다른 이슈와 겹치는 파일이 적음

좋은 예시:
- "Supabase Auth로 Google 로그인 구현"
- "Playlist 생성 폼과 validation 추가"
- "PA 민팅 요청 API route 추가"
- "사용자 프로필에 감성 로그 1일 1회 작성 제한 추가"

나쁜 예시:
- "서비스 전체 MVP 만들어줘"

---

## 5. 실제 분업 워크플로우

### Phase 1. 기획 확정
Gemini에 먼저 넣을 것:
- 현재 기획 초안
- 시장 가설
- 사용자 세그먼트
- 핵심 리스크

Gemini 산출물:
- PRD v1
- 사용자 시나리오
- 핵심 엔티티 정의
- MVP 범위 / 비MVP 범위

그 다음 Claude에 넘길 것:
- PRD v1
- 사용자 시나리오
- 브랜드 톤

Claude 산출물:
- IA
- 사용자 플로우
- 화면 목록
- 페이지별 UI 스펙
- 카피 초안

이 단계에서 사람은 `무엇을 만들지`를 확정한다.

---

### Phase 2. 기술 설계
Gemini에 맡길 것:
- Supabase ERD 초안
- Storage 구조 초안
- 이벤트 로그 설계
- 데이터 라이선싱 관점 엔티티 분리

Claude에 맡길 것:
- 프론트 상태 흐름
- 빈 상태 / 오류 상태 / 로딩 상태 설계

Codex에 맡길 것:
- 실제 리포지토리 초기화
- Next.js app router 구조
- Supabase client/server 분리
- lint/test/base layout 셋업

이 단계에서 사람은 `블록체인 기능을 MVP에 어디까지 넣을지`를 잘라야 한다.

권장:
- MVP 1차에서는 온체인 민팅보다 `오프체인 자산 등록 + 증명 메타데이터 구조화`를 우선한다.

---

### Phase 3. 구현 병렬화
이 단계부터 Codex 앱과 CLI를 같이 쓰는 것이 좋다.

권장 병렬 배치:
- Codex CLI: 백엔드/API/Auth
- Codex 앱 Agent 1: 프론트 핵심 플로우
- Codex 앱 Agent 2: 테스트/QA/리팩터링
- Claude: 랜딩/카피/디자인 디테일 보강
- Gemini: 정책 문서, 데이터 구조 검증, 투자/사업 설명 문안 보강

핵심 규칙:
- 같은 파일을 두 에이전트가 동시에 만지지 않게 한다.
- 작업 전 이슈에 수정 범위를 적는다.
- 완료 후에는 PR 설명을 표준 포맷으로 남긴다.

---

### Phase 4. 검증
검증은 AI 한 종류에 몰지 않는다.

권장 방식:
- Codex: 테스트 실행, 타입 체크, lint
- Claude: UX 회귀 검토
- Gemini: 논리적 누락, 정책/비즈니스 설명 모순 검토

사람 체크포인트:
- 이 기능이 정말 "인간 진본 데이터"라는 서사와 연결되는가
- 수익 모델이 과도하게 앞서가고 있지 않은가
- 개인정보/규제 리스크가 MVP에 과도하게 들어오지 않았는가

## 6. 추천 프롬프트 운영법

### Gemini에 줄 프롬프트 유형
- "이 PRD를 투자자/개발팀/정책팀 관점으로 각각 재구성해줘"
- "Supabase 기준으로 ERD와 RLS 고려사항까지 설계해줘"
- "MVP와 연구개발 항목을 분리해줘"

### Claude에 줄 프롬프트 유형
- "이 사용자 플로우를 기준으로 모바일 우선 화면 스펙을 작성해줘"
- "감성 기반 제품 톤으로 onboarding 카피를 써줘"
- "플레이리스트 생성, 기록 업로드, 검증 뱃지 표시 흐름의 UX를 설계해줘"

### Codex에 줄 프롬프트 유형
- "이 이슈를 구현하고 테스트까지 통과시켜줘"
- "이 PRD/화면 스펙 기준으로 app router 구조를 잡아줘"
- "현재 브랜치에서 auth 관련 구현만 수정하고 다른 기능은 건드리지 마"

## 7. 비용 대비 효율이 좋은 실제 조합

가장 실전적인 조합은 아래다.

### 조합 A. 균형형
- Gemini AI Pro
- Claude Pro
- ChatGPT Plus + Codex CLI/앱

적합:
- 1인 창업
- 초기 MVP
- 빠른 기획-구현 반복

장점:
- 기획, UX, 구현의 역할 분리가 선명하다.
- 비용 대비 효율이 높다.

---

### 조합 B. 구현 가속형
- Gemini AI Pro
- Claude Max 또는 상위 플랜
- ChatGPT Plus 이상 + Codex 앱 적극 활용

적합:
- 병렬 구현량이 많은 경우
- 여러 브랜치를 동시에 돌릴 경우

장점:
- Claude와 Codex를 동시에 많이 돌릴수록 구현 속도가 올라간다.

---

### 조합 C. 현실적 최소형
- ChatGPT Plus + Codex CLI/앱
- Claude Pro

적합:
- 이미 기획력이 충분하고 시장 리서치 비중이 낮을 때

보완:
- 긴 문맥 구조화와 리서치 정리는 약해질 수 있다.

## 8. 최종 추천

이 프로젝트 기준 최적 운영은 다음과 같다.

- `Gemini`: PRD, ERD, 정책/사업 구조
- `Claude`: UX, 카피, 프론트 스펙
- `Codex CLI`: 구현, 수정, 테스트
- `Codex 앱`: 병렬 작업 조정, 리뷰, 자동화
- `GitHub + Supabase + Playwright + Foundry`: 실행 인프라

중요한 건 "어느 AI가 더 똑똑하냐"보다 "어느 AI가 어느 산출물에 책임을 지느냐"다.

가장 비효율적인 방식은 모든 AI에게 같은 큰 프롬프트를 반복해서 던지는 방식이다.

가장 효율적인 방식은:
- 먼저 문서로 고정하고
- 그 문서를 이슈로 분해하고
- 각 AI에 역할을 고정하고
- 최종 판단만 사람이 하는 구조다.
