# Briefing: po-profile-curation-policy-001

## Role

Act as the Product Owner. Produce a decision-ready policy, not implementation code.

## Objective

Resolve the deferred question from the feedback completion report: whether user profiles are public curation spaces and which playlist assets appear there.

## Inputs

- `docs/20-product/strategy/product-baseline-v2.1.md`
- `docs/10-operations/feedback-fix-completion-report.md`
- `docs/20-product/design/ux/user-flows-v0.2-social.md`

## Output

Write only:

`docs/20-product/strategy/profile-curation-policy-v0.1.md`

## Required Decisions

- Recommend the MVP default for newly created assets: private, link-only, or public.
- Define visibility states and transitions.
- Define what appears on another user's profile.
- Define which Emotional Context fields remain private even when an asset is public.
- Define how gifts and shared links affect visibility.
- Define minimal acceptance criteria for backend and frontend implementation.
- List unresolved legal or abuse risks separately.

## Constraints

- Do not introduce direct messages or real-time features.
- Do not include B2B data sales, blockchain, Spotify, or Apple integration.
- Favor the smallest policy compatible with gift-first sharing and public social discovery.
