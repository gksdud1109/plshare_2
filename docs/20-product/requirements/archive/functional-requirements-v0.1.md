# Functional Requirements v0.1

## 문서 정보
- Version: `v0.1`
- Based on: `docs/20-product/strategy/archive/prd-v0.1.md`, `docs/20-product/requirements/playlist-first-product-intent.md`
- Scope: `playlist-first MVP`

---

## 1. 목적
이 문서는 `plshare2`의 MVP 1차 기능 요구사항을 더 구체적인 실행 단위로 정의한다.

핵심 기준:
- 첫 제품 단위는 `Playlist Asset`
- 감정 맥락이 붙은 인간 생성 플레이리스트가 핵심 객체
- C2C와 C2B 확장 가능성을 염두에 두되, MVP는 작성과 보기, 가벼운 상호작용, 데이터 구조화에 집중

---

## 2. 핵심 도메인 객체
- User
- Playlist Asset
- Playlist Track
- Asset Cover
- Diary Entry
- Note / Letter
- Proof Metadata
- Interaction
- Gift Transaction
- Purchase Intent or Purchase Record
- Data Consent

## 3. 인증 및 계정

### FR-001. 계정 생성 및 로그인
사용자는 소셜 로그인 기반으로 가입하고 로그인할 수 있어야 한다.

수용 기준:
- 이메일 또는 소셜 계정으로 가입 가능
- 첫 로그인 후 기본 프로필 생성
- 로그인 상태 유지 가능

### FR-002. 프로필 관리
사용자는 닉네임, 프로필 이미지, 자기소개를 수정할 수 있어야 한다.

---

## 4. 플레이리스트 에셋 생성

### FR-010. 플레이리스트 에셋 생성
사용자는 새로운 Playlist Asset을 생성할 수 있어야 한다.

입력 필수:
- 제목
- 곡 목록 1개 이상

입력 선택:
- 설명
- 감정 태그
- 상황 태그
- 커버 이미지
- 일기
- 짧은 메모
- 쪽지/편지

수용 기준:
- 초안 저장 가능
- 공개 전 수정 가능
- 필수 입력 누락 시 검증 메시지 표시

### FR-011. 곡 검색 및 추가
사용자는 외부 음악 메타데이터를 기반으로 곡을 검색하고 추가할 수 있어야 한다.

수용 기준:
- 검색어로 곡/아티스트 조회 가능
- 곡 제목, 아티스트, 앨범아트 등 기본 메타데이터 저장
- 플레이리스트 내 곡 순서 변경 가능

### FR-012. 감정 맥락 첨부
사용자는 Playlist Asset에 커버 사진, 일기, 짧은 글, 쪽지/편지를 첨부할 수 있어야 한다.

수용 기준:
- 텍스트 영역 분리 가능
- 커버 이미지는 업로드 후 미리보기 가능
- 저장 후 상세 페이지에서 함께 노출

### FR-013. 공개 설정
사용자는 Playlist Asset을 초안, 비공개, 공개 상태로 관리할 수 있어야 한다.

---

## 5. 인간 생성 증명

### FR-020. 생성 메타데이터 수집
시스템은 Playlist Asset 생성 시점의 기본 메타데이터를 수집해야 한다.

최소 범위:
- 생성 시각
- 수정 시각
- 클라이언트 환경 정보
- 편집 횟수

선택 동의 시:
- 위치 관련 정보
- 이미지 원본 메타데이터

### FR-021. 인간 생성 휴리스틱 기록
시스템은 인간 생성 여부를 추정하기 위한 휴리스틱 지표를 저장해야 한다.

예시:
- 입력 지속 시간
- 편집 패턴
- 붙여넣기 비율
- 업로드/작성 순서

주의:
- MVP에서는 최종 판정 엔진보다 `메타데이터 축적`이 우선

### FR-022. 검증 상태 표시
Playlist Asset 상세 화면에는 인간 생성 관련 상태를 표시할 수 있어야 한다.

예시:
- 검증 대기
- 기본 검증 통과
- 검증 정보 부족

---

## 6. 플레이리스트 에셋 보기 및 탐색

### FR-030. 내 자산 목록
사용자는 자신이 생성한 Playlist Asset 목록을 볼 수 있어야 한다.

### FR-031. 상세 페이지
사용자는 Playlist Asset 상세 페이지에서 아래 정보를 볼 수 있어야 한다.
- 제목
- 설명
- 커버 이미지
- 감정/상황 태그
- 곡 목록
- 일기/글/쪽지/편지
- 작성자
- 생성 시점
- 검증 상태

### FR-032. 피드 또는 탐색 목록
사용자는 공개된 Playlist Asset을 탐색할 수 있어야 한다.

초기 정렬 후보:
- 최신순
- 인기순
- 선물 많이 받은 순

## 7. 상호작용

### FR-040. 좋아요 / 저장
사용자는 Playlist Asset에 좋아요를 남기거나 저장할 수 있어야 한다.

### FR-041. 공유
사용자는 Playlist Asset을 링크로 공유할 수 있어야 한다.

### FR-042. 랭킹 집계
시스템은 플레이리스트 랭킹 산정에 필요한 상호작용 지표를 저장해야 한다.

초기 지표 예시:
- 조회 수
- 저장 수
- 좋아요 수
- 선물 수

---

## 8. 구매 및 선물

### FR-050. 선물하기
사용자는 공개된 Playlist Asset을 다른 사용자에게 선물할 수 있어야 한다.

MVP 해석:
- 반드시 블록체인 이전/민팅일 필요는 없음
- 포인트 기반 또는 디지털 카드형 선물도 허용

수용 기준:
- 수신자 지정 가능
- 선물 메시지 작성 가능
- 수신자는 받은 선물을 확인 가능

### FR-051. 구매 의사 표현 또는 구매
사용자는 특정 Playlist Asset에 대해 구매 의사를 표시하거나, 제한된 형태로 구매할 수 있어야 한다.

MVP 권장:
- 즉시 정식 거래보다 `구매 관심`, `가격 제안`, `한정 판매 실험` 중 하나를 먼저 검증

### FR-052. 감성적 패키징
선물 및 구매 화면은 단순 결제 UI가 아니라 감정 전달 경험을 제공해야 한다.

필수 요소 예시:
- 커버 시각 강조
- 작성자의 메시지
- 선물 카드형 표현
- 수신자용 오픈 경험

---

## 9. 데이터 판매 준비

### FR-060. 데이터 판매 동의
사용자는 자신의 Playlist Asset이 기업용 데이터셋 판매 대상에 포함될지 선택할 수 있어야 한다.

수용 기준:
- 동의 상태를 명시적으로 저장
- 철회 가능
- 동의 범위를 구분 가능

### FR-061. 판매 가능 데이터 구조화
시스템은 Playlist Asset을 기업용 데이터셋 단위로 재구성할 수 있어야 한다.

포함 대상:
- 음악 메타데이터
- 감정 태그
- 텍스트 기록
- 이미지 및 메타데이터
- 인간 생성 관련 메타데이터
- 익명화 상태

### FR-062. 내부용 데이터셋 목록
관리자 또는 내부 운영자는 판매 가능한 데이터셋 후보를 조회할 수 있어야 한다.

---

## 10. 운영 및 관리자 기능

### FR-070. 신고 및 비공개 처리
운영자는 부적절한 콘텐츠를 숨기거나 검토 상태로 전환할 수 있어야 한다.

### FR-071. 검증 로그 조회
운영자는 인간 생성 관련 메타데이터와 상태 로그를 확인할 수 있어야 한다.

### FR-072. 데이터 동의 상태 조회
운영자는 판매 동의 상태별로 자산을 필터링할 수 있어야 한다.

---

## 11. MVP 우선순위

### Must Have
- 계정 생성/로그인
- Playlist Asset 생성
- 곡 검색/추가
- 커버/일기/글 첨부
- 기본 메타데이터 수집
- 상세 페이지
- 좋아요/저장
- 데이터 판매 동의 저장

### Should Have
- 공개 탐색 목록
- 랭킹 집계
- 선물하기 MVP
- 검증 상태 표시

### Could Have
- 구매 관심 표시
- 운영자 데이터셋 조회 화면

### Deferred
- 온체인 민팅
- 정교한 스마트 컨트랙트 거래
- 웨어러블 실시간 연동
- ZK 기반 증명
