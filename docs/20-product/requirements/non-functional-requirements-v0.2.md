# Non-Functional Requirements v0.2

## 문서 정보
- Version: `v0.2`
- Based on: `docs/20-product/strategy/prd-v0.2.md`, `docs/20-product/research/market-research-v0.3.md`
- Scope: `playlist asset ledger MVP`

---

## 1. 목적
이 문서는 `prd-v0.2` 기준 MVP가 갖춰야 할 품질 속성과 운영 기준을 정의한다.

핵심 초점:
- 플랫폼 연동 제품으로서의 안정성
- 감성 기록 서비스로서의 신뢰성
- 정책 리스크를 줄이는 구조적 안전성

---

## 2. 사용성

### NFR-001. 첫 가치 도달 시간
신규 사용자는 가입 후 짧은 흐름 안에 첫 번째 핵심 가치에 도달할 수 있어야 한다.

MVP 기준 핵심 가치:
- 외부 플레이리스트 1개 가져오기 완료
- 또는 빈 자산 초안 생성 완료

권장 목표:
- 첫 핵심 가치 도달까지 5분 이내

### NFR-002. 단계 최소화
핵심 흐름 `가져오기 -> 맥락 추가 -> 저장 -> 공유/내보내기`는 불필요한 화면 전환 없이 수행 가능해야 한다.

### NFR-003. 감성 표현 품질
상세 페이지와 공유 페이지는 단순 데이터 테이블이 아니라 커버, 문장, 태그의 의미가 살아나는 수준의 표현력을 가져야 한다.

### NFR-004. 실패 회복 가능성
가져오기, 이미지 업로드, 내보내기 중 일부 단계가 실패해도 사용자는 전체 작성 상태를 잃지 않고 복구 경로를 볼 수 있어야 한다.

---

## 3. 성능

### NFR-010. 일반 조회 응답성
일반적인 모바일 네트워크 환경에서 아래 요청은 95퍼센타일 기준 빠르게 응답해야 한다.

대상:
- 내 자산 목록 조회
- 자산 상세 조회
- 공개 자산 목록 조회

권장 목표:
- API 응답 1.5초 이내

### NFR-011. 가져오기 처리 시간
100곡 이하 플레이리스트 기준 가져오기 작업은 외부 플랫폼 지연을 제외한 내부 처리 관점에서 실용적인 시간 안에 완료되어야 한다.

권장 목표:
- 내부 파이프라인 처리 30초 이내

### NFR-012. 내보내기 시작 응답성
내보내기 버튼 클릭 후 사용자가 작업이 시작되었음을 3초 이내에 인지할 수 있어야 한다.

### NFR-013. 자동 저장 안정성
텍스트 편집 중 작성 내용은 주기적으로 자동 저장되거나 이와 동등한 수준으로 유실 방지되어야 한다.

권장 목표:
- 마지막 변경 후 5초 이내 저장 시도

---

## 4. 신뢰성 및 데이터 무결성

### NFR-020. 자산 원본성 보존
가져온 외부 플레이리스트 원본 정보와 내부 `Playlist Asset` 정보는 구분 저장되어야 한다.

### NFR-021. 트랙 순서 무결성
가져오기와 내보내기 과정에서 트랙 순서는 의도치 않게 변경되지 않아야 한다.

### NFR-022. 부분 성공 허용
가져오기 및 내보내기 작업은 일부 트랙 실패를 허용하되, 성공/실패 내역을 명확히 기록해야 한다.

### NFR-023. 작업 재시도 안정성
네트워크 오류나 외부 API 오류 발생 시 동일 작업을 안전하게 재시도할 수 있어야 한다.

### NFR-024. 감사 추적 가능성
아래 상태 변경은 추적 가능해야 한다.

대상:
- 공개 상태 변경
- 동의 상태 변경
- 내보내기 실행
- 운영자 비공개 처리

---

## 5. 외부 플랫폼 정책 준수

### NFR-030. 비재생 중심 구조
MVP는 앱 내부 상업적 스트리밍 엔진에 의존하지 않아야 한다.

### NFR-031. 플랫폼별 adapter 분리
Spotify, Apple Music, 향후 YouTube adapter는 공통 인터페이스 위에서 분리 구현 가능해야 한다.

### NFR-032. 최소 권한 사용
외부 플랫폼 OAuth 권한은 필요한 범위로 제한해야 한다.

### NFR-033. 정책 변경 대응성
플랫폼별 권한 범위, rate limit, write 제한이 변경되어도 특정 adapter만 제한하거나 비활성화할 수 있어야 한다.

### NFR-034. 정책 고지
사용자에게 아래 사항을 명확히 고지할 수 있어야 한다.

- 어떤 플랫폼 계정이 연결되는지
- 어떤 데이터가 읽히는지
- 어떤 데이터가 쓰이는지
- 매칭 실패로 일부 곡이 누락될 수 있다는 점

---

## 6. 보안

### NFR-040. 접근 제어
비공개 자산, 초안, 민감 메타데이터는 권한 있는 사용자와 운영자만 접근 가능해야 한다.

### NFR-041. 안전한 저장
민감도가 높은 텍스트 및 메타데이터는 저장 시 보호되어야 한다.

최소 범위:
- 일기/메모
- 위치 관련 신호
- 이미지 원본 메타데이터
- OAuth 토큰

### NFR-042. 비밀정보 관리
외부 플랫폼 클라이언트 시크릿과 액세스 토큰은 코드 저장소나 클라이언트에 노출되어서는 안 된다.

### NFR-043. 운영자 권한 분리
운영자 기능, 일반 사용자 기능, 내부 데이터 검토 기능은 최소 권한 원칙에 따라 분리되어야 한다.

---

## 7. 개인정보 및 동의

### NFR-050. 기본 비동의 원칙
민감 데이터 수집과 B2B 후보 포함은 기본적으로 opt-in이어야 한다.

### NFR-051. 동의 철회 가능성
사용자는 이후 언제든지 동의를 철회할 수 있어야 하며, 철회 후 신규 처리에는 반영되어야 한다.

### NFR-052. 최소 수집
MVP에서는 제품 가치 검증에 꼭 필요한 정보만 수집해야 한다.

우선 제외 권장:
- 상시 위치 추적
- 상시 센서 수집
- 생체 정보

### NFR-053. 데이터 분리 저장
개인 식별 정보, 자산 본문 데이터, 증명 신호, 향후 B2B용 익명화 데이터는 논리적으로 분리 가능해야 한다.

### NFR-054. 삭제 대응성
계정 삭제 또는 자산 삭제 요청 시 연관 데이터의 삭제 또는 비식별화 범위를 정의하고 실행할 수 있어야 한다.

---

## 8. 설명 가능성과 신뢰

### NFR-060. 매칭 결과 설명 가능성
사용자는 왜 특정 곡이 매칭되었는지 또는 누락되었는지 최소한의 설명을 볼 수 있어야 한다.

### NFR-061. 인간성 검증의 비과장
MVP에서 인간 생성 관련 상태는 보조 신호로 표현해야 하며, 절대적 진위 판정처럼 보이면 안 된다.

### NFR-062. 사용자 기대 관리
공유 페이지와 내보내기 화면에서는 아래 사실을 명확히 전달해야 한다.

- 실제 음악은 외부 플랫폼에서 소비된다
- 일부 곡은 플랫폼 카탈로그 차이로 빠질 수 있다
- 감성 자산의 핵심은 맥락과 구조라는 점

---

## 9. 확장성 및 아키텍처

### NFR-070. Canonical data 우선 구조
내부 핵심 데이터 모델은 특정 플랫폼 ID 하나에 종속되지 않아야 한다.

### NFR-071. Adapter 확장성
향후 Tidal, Deezer, YouTube 등을 추가할 때 코어 도메인 모델 변경을 최소화해야 한다.

### NFR-072. 배치 및 비동기 처리 가능성
가져오기, 정규화, 내보내기는 장기적으로 큐 기반 비동기 작업으로 분리 가능해야 한다.

### NFR-073. B2B 전환 준비성
향후 기업용 패키지 추출 시 Spotify 원본 콘텐츠를 제외하고 사용자 작성 맥락과 익명화된 구조 데이터만 추출할 수 있어야 한다.

---

## 10. 운영성 및 관측 가능성

### NFR-080. 핵심 이벤트 로깅
아래 이벤트는 로그 및 지표로 확인 가능해야 한다.

- 로그인 성공/실패
- 가져오기 시작/완료/실패
- 매칭 성공률
- 내보내기 시작/완료/실패
- 동의 저장/철회
- 공유 링크 조회

### NFR-081. 운영자 가시성
운영자는 플랫폼별 실패율, 매칭 실패율, 이미지 업로드 실패율을 확인할 수 있어야 한다.

### NFR-082. 장애 격리
특정 플랫폼 adapter의 장애가 전체 서비스의 자산 보기 및 편집 기능까지 중단시키면 안 된다.

### NFR-083. 알림 가능성
가져오기 또는 내보내기 완료 후 사용자에게 앱 내 상태 알림을 제공할 수 있어야 한다.

---

## 11. 품질 보증

### NFR-090. 핵심 회귀 테스트 대상
아래 흐름은 회귀 테스트 우선순위가 높아야 한다.

- Spotify 가져오기
- Apple Music 가져오기
- 정규화 및 매칭
- 자산 저장과 재편집
- 내보내기
- 공개/비공개 접근 제어

### NFR-091. 샘플 데이터셋 기반 검증
플랫폼별 대표 플레이리스트 샘플로 매칭 정확도와 누락률을 반복 측정할 수 있어야 한다.

### NFR-092. 안전한 점진 배포
새 adapter 또는 플랫폼 쓰기 기능은 기능 플래그 또는 점진 배포 방식으로 활성화 가능해야 한다.

---

## 12. MVP 기준 요약

MVP에서 특히 중요한 비기능 요구사항은 아래 6가지다.

1. 첫 가져오기/저장까지의 마찰이 낮을 것
2. 가져오기와 내보내기가 부분 실패를 견디며 복구 가능할 것
3. 감성 기록과 OAuth 자격 정보가 안전하게 보호될 것
4. 플랫폼 정책 변화에 대응 가능한 adapter 구조일 것
5. 매칭 실패와 인간성 신호를 과장 없이 설명할 수 있을 것
6. 향후 B2B 전환 시 원본 음원 의존을 줄일 수 있을 것
