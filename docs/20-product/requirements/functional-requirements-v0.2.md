# Functional Requirements v0.2

## 문서 정보
- Version: `v0.2`
- Based on: `docs/20-product/strategy/prd-v0.2.md`, `docs/20-product/requirements/playlist-first-product-intent.md`, `docs/20-product/research/market-research-v0.3.md`
- Scope: `playlist asset ledger MVP`

---

## 1. 목적
이 문서는 `prd-v0.2`를 실제 설계와 구현 단위로 풀어낸 기능 요구사항이다.

이번 버전의 핵심 해석:
- 제품의 1차 가치는 `재생`이 아니라 `가져오기 -> 자산화 -> 내보내기/공유`
- 핵심 객체는 `Playlist Asset`이며, 음원 파일은 저장하거나 판매하지 않는다
- MVP는 `플랫폼 이동성`과 `감성 맥락 저장`을 검증하는 데 집중한다

---

## 2. MVP 제품 원칙

### 2.1 반드시 포함할 가치
- 사용자는 외부 스트리밍 서비스의 플레이리스트를 가져올 수 있어야 한다
- 가져온 플레이리스트를 플랫폼 비종속 자산으로 저장할 수 있어야 한다
- 자산에 감성 맥락을 붙일 수 있어야 한다
- 자산을 다른 플랫폼으로 내보내거나 링크로 공유할 수 있어야 한다

### 2.2 MVP에서 의도적으로 축소할 범위
- 앱 내부의 본격적인 음악 재생 엔진
- 복잡한 선물/결제/정산 시스템
- 기업용 데이터 판매 워크플로
- 강한 자동 인간 판정 엔진

## 4. 인증 및 계정

### FR-001. 계정 생성 및 로그인
사용자는 이메일 또는 소셜 로그인 기반으로 가입하고 로그인할 수 있어야 한다.

수용 기준:
- 첫 로그인 시 기본 프로필이 생성된다
- 사용자는 로그인 상태를 유지할 수 있다
- 탈퇴 또는 계정 비활성화 절차가 제공된다

### FR-002. 기본 프로필 관리
사용자는 닉네임, 프로필 이미지, 자기소개를 수정할 수 있어야 한다.

### FR-003. 스트리밍 계정 연결
사용자는 Spotify 또는 Apple Music 계정을 연결하거나 연결 해제할 수 있어야 한다.

수용 기준:
- 연결 상태가 사용자에게 명확히 표시된다
- 연결 해제 시 이후 자동 동기화 및 쓰기 작업이 중단된다
- 연결 실패 사유를 사용자에게 표시한다

## 5. 가져오기(Import)

### FR-010. 플레이리스트 가져오기 시작
사용자는 두 가지 방식 중 하나로 플레이리스트를 가져올 수 있어야 한다.

지원 방식:
- URL 기반 가져오기
- OAuth 기반 계정 연결 후 목록 선택

우선 지원 대상:
- Spotify
- Apple Music

수용 기준:
- URL이 유효하지 않으면 에러를 표시한다
- 권한이 필요한 경우 연결 플로우로 안내한다
- 가져오기 시작 후 진행 상태를 확인할 수 있다

### FR-011. 외부 플레이리스트 메타데이터 수집
시스템은 외부 플레이리스트에서 아래 정보를 수집할 수 있어야 한다.

최소 수집 항목:
- 외부 플랫폼명
- 외부 플레이리스트 ID 또는 URL
- 제목
- 설명
- 작성자명 또는 표시 가능한 소유자 정보
- 곡 목록
- 곡 순서

### FR-012. 대량 트랙 가져오기
시스템은 외부 플레이리스트의 트랙 목록을 순서대로 가져와야 한다.

수용 기준:
- 순서 정보가 보존된다
- 일부 곡 가져오기에 실패해도 전체 작업이 즉시 중단되지 않는다
- 실패 항목 수를 사용자에게 표시한다

### FR-013. 가져오기 이력
사용자는 최근 가져오기 작업 내역과 결과를 확인할 수 있어야 한다.

표시 항목 예시:
- 소스 플랫폼
- 시작 시간
- 완료 상태
- 총 곡 수
- 매칭 실패 곡 수

## 6. 정규화(Normalization)

### FR-020. Canonical Track 생성
시스템은 가져온 각 트랙을 `Canonical Track`으로 정규화해야 한다.

최소 보존 필드:
- 트랙 제목
- 아티스트명
- 앨범명
- 재생시간 또는 길이 정보
- ISRC
- 플랫폼별 식별자

### FR-021. 매칭 우선순위
시스템은 아래 순서로 곡 매칭을 시도해야 한다.

1. ISRC 기반 정확 매칭
2. 플랫폼 ID 직접 매핑
3. 제목 + 아티스트 + 길이 기반 유사 매칭

### FR-022. 매칭 신뢰도 저장
시스템은 각 트랙 매칭 결과에 대해 신뢰도를 저장해야 한다.

상태 예시:
- exact
- high-confidence
- low-confidence
- unmatched

### FR-023. 매칭 실패 처리
매칭되지 않거나 신뢰도가 낮은 트랙은 사용자에게 해결 가능 상태로 표시되어야 한다.

수용 기준:
- 사용자는 실패 항목을 볼 수 있다
- 사용자는 대체 트랙 후보를 선택할 수 있다
- 사용자는 해당 트랙을 내보내기에서 제외할 수 있다

### FR-024. 정규화 결과 보존
정규화 결과는 이후 내보내기와 공유에 재사용할 수 있도록 저장되어야 한다.

---

## 7. Playlist Asset 생성 및 편집

### FR-030. Playlist Asset 생성
사용자는 가져온 플레이리스트를 기반으로 새로운 `Playlist Asset`을 생성할 수 있어야 한다.

필수 입력:
- 제목
- 곡 목록 1개 이상

선택 입력:
- 설명
- 커버 이미지
- 감정 태그
- 상황 태그
- 짧은 메모
- 일기
- 쪽지 또는 편지

### FR-031. 초안 저장
사용자는 `Playlist Asset`을 초안 상태로 저장할 수 있어야 한다.

수용 기준:
- 초안은 공개되지 않는다
- 초안은 이후 다시 편집할 수 있다
- 작성 도중 저장 실패 시 재시도 경로를 제공한다

### FR-032. 자산 편집
사용자는 자산 생성 후 아래 요소를 수정할 수 있어야 한다.

수정 가능 범위:
- 제목
- 설명
- 커버 이미지
- 감정/상황 태그
- 일기/메모/쪽지
- 트랙 제외 또는 순서 조정

### FR-033. 공개 상태 관리
사용자는 자산을 아래 상태로 관리할 수 있어야 한다.

상태:
- draft
- private
- public

### FR-034. 삭제 및 보관
사용자는 자산을 삭제하거나 보관 상태로 전환할 수 있어야 한다.

---

## 8. 감성 맥락(Context)

### FR-040. 텍스트 맥락 첨부
사용자는 하나의 자산에 감성 맥락 텍스트를 저장할 수 있어야 한다.

지원 종류:
- 설명
- 짧은 메모
- 일기
- 선물용 메시지 초안

### FR-041. 이미지 첨부
사용자는 커버 이미지 또는 감성 이미지를 업로드할 수 있어야 한다.

수용 기준:
- 업로드 후 미리보기를 제공한다
- 이미지 업로드 실패 시 텍스트 저장은 유지된다

### FR-042. 태그 입력
사용자는 감정 태그와 상황 태그를 입력할 수 있어야 한다.

예시:
- 비 오는 날
- 퇴근길
- 위로
- 집중

---

## 9. 인간 생성 신호(Proof Signal)

### FR-050. 기본 작성 메타데이터 수집
시스템은 자산 생성/수정 시점의 기본 메타데이터를 수집해야 한다.

최소 범위:
- 생성 시각
- 수정 시각
- 편집 횟수
- 입력 지속 시간
- 붙여넣기 여부 또는 비율

### FR-051. 선택 동의 기반 확장 신호
사용자가 동의한 경우에만 추가 신호를 수집할 수 있어야 한다.

선택 범위:
- 위치 관련 정보
- 이미지 EXIF 등 원본 메타데이터

### FR-052. 검증 상태 표시
시스템은 인간 생성 관련 상태를 사용자에게 표시할 수 있어야 한다.

표시 원칙:
- 확정 판정처럼 보이지 않아야 한다
- 상태와 부족한 정보 수준을 설명해야 한다

상태 예시:
- 정보 수집 중
- 기본 신호 확보
- 정보 부족

---

## 10. 보기, 공유, 열기

### FR-060. 내 자산 목록
사용자는 자신이 만든 자산 목록을 볼 수 있어야 한다.

최소 표시 항목:
- 제목
- 커버
- 공개 상태
- 소스 플랫폼
- 마지막 수정 시각

### FR-061. 자산 상세 페이지
사용자는 자산 상세 페이지에서 아래 정보를 볼 수 있어야 한다.

- 제목
- 설명
- 커버 이미지
- 감정/상황 태그
- 트랙 목록
- 맥락 텍스트
- 작성자
- 생성 시점
- 검증 상태
- 외부 앱에서 열기 버튼

### FR-062. 공개 링크 공유
사용자는 공개 자산을 링크로 공유할 수 있어야 한다.

수용 기준:
- 링크를 받은 사용자는 웹 감상 페이지를 열 수 있다
- 비로그인 사용자도 공개 범위 내에서 페이지를 볼 수 있다

### FR-063. 외부 앱에서 열기
시스템은 자산의 트랙 매핑 결과를 기반으로 연결 가능한 외부 플랫폼으로 열기 동작을 제공해야 한다.

수용 기준:
- 대상 플랫폼을 선택할 수 있다
- 연결되지 않은 플랫폼은 연결을 유도한다
- 매칭 실패 곡 수를 사전에 알려준다

## 11. 내보내기(Export)

### FR-070. 플랫폼 선택 내보내기
사용자는 자신의 자산을 지원 플랫폼으로 내보낼 수 있어야 한다.

MVP 우선 지원:
- Spotify
- Apple Music

### FR-071. 대상 플랫폼 플레이리스트 생성
시스템은 대상 플랫폼에 새 플레이리스트를 생성할 수 있어야 한다.

수용 기준:
- 제목과 설명을 전송한다
- 플랫폼 제약으로 누락되는 정보는 사용자에게 고지한다

### FR-072. 트랙 추가
시스템은 정규화된 트랙 매핑을 이용해 대상 플레이리스트에 트랙을 순서대로 추가해야 한다.

수용 기준:
- 매칭된 트랙만 추가된다
- 누락된 트랙 수를 결과에 포함한다

### FR-073. 내보내기 작업 상태
내보내기는 비동기 작업으로 처리할 수 있어야 하며, 사용자는 진행 상태를 볼 수 있어야 한다.

상태 예시:
- queued
- running
- completed
- partially completed
- failed

### FR-074. 중복 내보내기 보호
사용자가 동일 자산을 반복 내보내기할 때 중복 생성 위험을 인지할 수 있어야 한다.

수용 기준:
- 직전 내보내기 대상과 시각을 표시한다
- 재시도와 새로 내보내기를 구분한다

## 12. 탐색과 가벼운 상호작용

### FR-080. 공개 자산 탐색
사용자는 공개된 자산을 탐색할 수 있어야 한다.

초기 정렬:
- 최신순
- 저장 많은 순

### FR-081. 저장
사용자는 공개 자산을 저장할 수 있어야 한다.

### FR-082. 좋아요
사용자는 공개 자산에 좋아요를 남길 수 있어야 한다.

### FR-083. 작성자 페이지
사용자는 특정 작성자의 공개 자산 목록을 볼 수 있어야 한다.

---

## 13. 동의 및 데이터 사용 제어

### FR-090. 데이터 판매 관련 동의 저장
사용자는 자신의 자산이 향후 기업용 데이터셋 후보에 포함될지 여부를 선택할 수 있어야 한다.

수용 기준:
- 기본값은 비동의다
- 자산 단위로 동의 상태를 저장한다
- 사용자는 이후 철회할 수 있다

### FR-091. 민감 데이터 수집 동의
위치, 이미지 원본 메타데이터 등 민감 정보는 별도 동의를 받아야 한다.

### FR-092. 데이터 내보내기 및 삭제 요청 준비
시스템은 향후 사용자 데이터 내보내기 및 삭제 요청을 처리할 수 있도록 데이터 구조를 구분해 저장해야 한다.

## 14. 운영 및 관리자 기능

### FR-100. 신고 및 비공개 처리
운영자는 신고된 자산을 숨기거나 검토 상태로 전환할 수 있어야 한다.

### FR-101. 가져오기/내보내기 실패 로그 조회
운영자는 플랫폼 연동 실패 로그를 조회할 수 있어야 한다.

### FR-102. 매칭 실패 현황 조회
운영자는 매칭 실패율이 높은 플랫폼 또는 자산을 확인할 수 있어야 한다.

### FR-103. 동의 상태 조회
운영자는 데이터 활용 동의 상태별로 자산을 필터링할 수 있어야 한다.

## 15. MVP 우선순위 요약

### Must Have
- 계정 생성 및 로그인
- Spotify/Apple Music 플레이리스트 가져오기
- 정규화 및 매칭 신뢰도 저장
- 매칭 실패 항목 표시
- Playlist Asset 생성/초안/공개
- 커버 이미지, 메모, 일기, 태그 첨부
- 자산 상세 페이지
- 공개 링크 공유
- Spotify/Apple Music 내보내기
- 동의 저장

### Should Have
- OAuth 기반 목록 선택 가져오기
- 저장/좋아요
- 공개 탐색 목록
- 작성자 페이지
- 기본 운영자 로그 조회

### Could Have
- 수동 대체 트랙 추천 고도화
- 선물 메시지 초안 저장
- 가져오기 이력의 재실행 기능
