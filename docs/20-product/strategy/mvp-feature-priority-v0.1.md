## 1. 목적
이 문서는 `prd-v0.2`를 실제 MVP 범위로 압축하기 위한 우선순위 문서다.

핵심 원칙:
- MVP는 `취향 자산을 플랫폼 밖으로 꺼내 보존하고 다시 연결하는 경험`을 증명해야 한다
- 하나의 릴리즈에서 너무 많은 가치를 동시에 증명하려 하지 않는다
- `정책 리스크가 큰 기능`과 `운영 복잡도가 큰 기능`은 뒤로 미룬다

---

## 2. 전략가 관점의 현실 점검

### 2.1 좋은 점
- `음악 재생 서비스`에서 `취향 자산 레이어`로의 재정의는 맞는 방향이다
- 저작권과 플랫폼 정책 리스크를 줄이면서도 차별 포인트를 만들 수 있다
- `import/export`는 실제 유입 훅으로 작동할 가능성이 있다

### 2.2 현실적으로 조심할 점
- `Cross-platform Bridge`, `Human-Authenticity`, `B2B 준비`, `공유/소셜`, `선물/결제`를 동시에 잡으면 MVP가 흐려진다
- 사용자가 처음 돈을 내는 이유는 아직 불명확하다. 따라서 `결제/선물`은 코어 검증 이후가 낫다
- `Proof-of-Human`은 제품 신뢰를 높일 수 있지만, 초기에 구현 난도와 프라이버시 부담이 빠르게 커진다
- 플랫폼 연동 제품의 실제 난점은 화려한 UX보다 `매칭 오류`, `부분 실패`, `재시도`, `권한 만료`다

### 2.3 현실적 MVP 질문
MVP가 답해야 할 질문은 아래 3개면 충분하다.

1. 사용자는 외부 플레이리스트를 가져와 `자산`으로 저장할 의향이 있는가?
2. 사용자는 단순 목록보다 `커버 + 글 + 태그`가 붙은 자산에 더 큰 가치를 느끼는가?
3. 사용자는 그 자산을 다시 다른 플랫폼으로 내보내거나 공유하고 싶은가?

---

## 3. MVP의 단일 핵심 루프

### 핵심 루프
`Import -> Normalize -> Add Context -> Save Asset -> Export or Share`

### 이 루프를 선택하는 이유
- 제품의 차별점과 실용성을 동시에 검증한다
- 정책 리스크가 큰 `인앱 상업 재생` 없이도 성립한다
- 향후 선물, 수집, B2B로 확장 가능한 데이터 구조를 남긴다

---

## 4. 우선순위 프레임

### Tier 0. 출시 불가를 막는 기반 (Strategic P0)
이 단계가 없으면 MVP는 실제 사용 불가다.

- 계정 생성 및 로그인
- Spotify 가져오기 연결
- Apple Music 내보내기 연결
- 가져오기 작업 상태 관리
- 정규화 및 매칭 결과 저장
- 초안 저장
- 자산 상세 조회
- 공개/비공개 접근 제어
- 기본 로그와 오류 추적

### Tier 1. 반드시 출시해야 하는 코어 (Strategic P0)
이 단계가 있어야 사용자가 제품의 핵심 가치를 경험한다.

- Spotify 플레이리스트 URL 또는 OAuth 기반 가져오기
- Canonical Track 정규화
- 매칭 실패 항목 표시
- 자산 제목/설명/태그/일기/커버 편집
- 공개 링크 공유
- Apple Music으로 내보내기

### Tier 2. 출시 직후 빠르게 붙일 기능 (Strategic P1)
없어도 MVP는 가능하지만, 리텐션과 탐색성을 높인다.

- 선택 동의 기반의 기본 proof signal 수집 (작성 패턴 등)
- 공개 자산 탐색 목록
- 저장 / 좋아요 / 작성자 팔로우
- 작성자 페이지
- 수동 대체 트랙 선택 UX 개선
- 내보내기 이력 및 재시도 UX 개선

### Tier 3. Post-MVP (Strategic P2)
핵심 가설 검증 이후에 붙이는 것이 맞다.

- 선물하기 / 결제 / 랭킹
- YouTube adapter 본격화
- 고도화된 인간성 점수 (센서 등)
- B2B 판매 콘솔

## 5. Must / Should / Could / Won't

### Must (P0)
- 로그인 및 계정 관리
- Spotify import
- Apple Music export
- 정규화 결과 저장 및 매칭 실패 처리
- 감성 맥락(일기/이미지/태그) 입력 및 자산 저장
- 공개 링크 공유

### Should (P1)
- 저장/좋아요/팔로우
- 탐색 피드 및 작성자 페이지
- 기본 proof signal 수집

### Could (P1.5)
- 수동 트랙 대체 추천
- 가져오기 이력 재실행
- 선물 메시지 초안

### Won't for MVP (P2)
- 앱 내부 본격 음악 재생
- 결제/정산 및 실제 선물하기
- NFT/온체인 민팅
- 기업 판매 워크플로 및 YouTube adapter
- 강한 인간 인증 (Biometrics)

---

## 6. 합의된 출시 범위

### 현재 동결된 1차 출시안
- Spotify import
- Apple Music export
- 자산 생성/편집
- 커버/일기/태그
- 공개 링크 공유

장점:
- `다른 플랫폼으로 옮긴다`는 가치가 가장 선명하다
- 한쪽은 읽기, 한쪽은 쓰기로 나눠 구현 복잡도를 줄일 수 있다

리스크:
- 양방향 브리지처럼 보이지 않을 수 있다

현재 기준:
- 양방향 브리지는 P1로 미룬다
- P0에서는 이 안을 벗어난 대체 출시안을 두지 않는다

## 8. 출시 체크리스트

출시 전 아래 항목이 충족되지 않으면 MVP 완성으로 보기 어렵다.

1. 20개 이상의 실제 플레이리스트 샘플에서 import/export가 반복 검증되었는가
2. 매칭 실패율과 누락 사유를 사용자에게 설명할 수 있는가
3. 일부 실패가 발생해도 자산 저장 자체는 유지되는가
4. 공유 링크가 로그인 없이도 핵심 가치를 전달하는가
5. OAuth 토큰, 일기, 이미지 메타데이터 보호가 확인되었는가

---

## 9. 최종 제언

`prd-v0.2`의 방향은 맞다. 다만 MVP는 더 좁혀야 한다.

가장 현실적인 컷라인은 아래다.

1. 외부 플레이리스트를 가져온다
2. 그것을 감성 맥락이 붙은 자산으로 저장한다
3. 그 자산을 다시 다른 플랫폼으로 내보내거나 링크로 공유한다

이 3단계를 안정적으로 만들기 전에는 선물, 결제, 랭킹, B2B를 넣지 않는 편이 맞다.  
지금 제품이 먼저 증명해야 하는 것은 `음악을 둘러싼 취향 자산의 이동성과 보존성`이지, 거래 시스템의 복잡함이 아니다.
