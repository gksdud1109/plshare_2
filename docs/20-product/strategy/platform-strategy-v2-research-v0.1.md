# Platform Strategy Review v0.2

## 1. Executive Summary
*   **플랫폼 우선순위 전면 재조정**: 사용자 수요가 압도적인 **YouTube Music(YTM)**을 P0로 격상, Spotify ↔ YTM 코리도를 최우선 확보.
*   **"딸깍" UX 실현**: 가져오기-자산화-내보내기 단계를 백그라운드로 자동화하여 사용자 체감 단계를 1-Step으로 단축.
*   **소셜 로그인 일원화**: Google OAuth를 기본 인증으로 채택하여 소셜 정체성 확립과 YouTube API 권한 획득의 시너지 극대화.
*   **감성 소셜 레이어 도입**: 단순 변환 도구를 넘어 플레이리스트를 '선물'하고 '기록'하는 음악 기반 SNS로 정체성 확장.
*   **단계적 API 대응**: YTM '읽기' 기반의 소셜 공유를 선출시하고, 쿼터 증설에 맞춰 '내보내기' 기능을 전면 개방하는 단계적 로드맵 이행.

## 2. 코리도 재검토 결론 (v0.1 대비 변경 사항)
v0.1에서는 API 안정성과 매칭 품질을 이유로 Apple Music을 P0로 두었으나, v0.2에서는 **시장 지배력 및 소셜 확장성**을 근거로 전략을 수정함.

| 코리도 | v0.1 순위 | **v0.2 순위** | 변경 사유 |
| :--- | :---: | :---: | :--- |
| **Spotify ↔ YTM** | P2 | **P0** | 국내외 압도적 점유율, Google 계정 기반 소셜 확장 용이성, '딸깍' UX 수요 최다. |
| **Spotify ↔ Apple** | P0 | **P1** | 매칭 품질은 높으나 고관여 유저 중심의 니치 시장으로 판단, 점진적 확장 대상으로 변경. |
| **YTM ↔ Apple** | P2 | **P1** | 플랫폼 이동 수요(Switching) 대응을 위해 중요도 상향. |

## 3. YouTube API 실현가능성 및 대응 전략
YouTube Data API v3의 엄격한 쿼터 제한(10,000 units/day)을 고려한 정교한 운영 전략 수립.

### 3.1. 쿼터 수치 검증 및 한계
*   **조회(Import)**: `playlists.list`, `playlistItems.list` 각 1 unit. → 사실상 무제한(하루 10,000회 가능).
*   **생성/내보내기(Export)**: `playlists.insert`(50 units) + `playlistItems.insert`(50 units/곡).
    *   **30곡 플레이리스트 1건 내보내기**: 50 + (30 * 50) = **1,550 units**.
    *   **일일 처리 가능량**: 약 **6.4건** (기본 쿼터 기준).
*   **결론**: 기본 쿼터 상태에서 전면적인 '내보내기' 서비스는 불가능함.

### 3.2. 단계적 돌파 전략
1.  **Phase 1 (YTM Import & Social)**: YouTube Music의 플레이리스트를 '가져와서' 우리 플랫폼 내에서 공유하고 즐기는 소셜 기능에 집중 (쿼터 소모 극소).
2.  **Phase 2 (Selective Export)**: 초기 활성 유저 또는 랭킹 상위 유저 대상 선착순/포인트제 내보내기 운영을 통해 쿼터 증설을 위한 실측 데이터(Use Case) 확보.
3.  **Phase 3 (Quota Expansion)**: 서비스 지표를 바탕으로 Google에 쿼터 증설 요청 (최소 100만 unit 이상 확보 추진).

### 3.3. 트랙 정규화 및 리스크 완화
*   **videoId 리스크**: YTM의 공식 음원이 아닌 사용자 업로드 영상(Cover, Fan-made)은 ISRC가 없어 정규화가 어려움.
*   **완화책**: MatchingEngine에서 ISRC 미매칭 시 `videoId` 기반의 Metadata(제목, 아티스트명) Fuzzy 매칭을 2순위로 적용하되, 'Low Confidence' 플래그를 부착하여 사용자 확인 절차 제공.

## 4. 인증 및 계정 전략
소셜 기능 활성화를 위해 '서비스 계정'과 '플랫폼 연결'을 분리하지 않고 통합하는 모델 채택.

*   **Google OAuth 우선순위 P0**: 
    *   하나의 ID로 서비스 가입 + YouTube 접근 권한(Scope) 획득.
    *   단계적 동의(Incremental Auth) 적용: 가입 시 기본 프로필만, YTM 연동 시점에 추가 권한 요청.
*   **멀티 플랫폼 연결**: 가입은 Google로 하되, 마이페이지 내에서 Spotify/Apple Music을 추가 연동하는 'Hub & Spoke' 모델.
*   **계정 연동 시너지**: Google 로그인 유저의 프로필(이름, 사진)을 즉시 소셜 프로필로 전환하여 가입 허들을 최소화.

## 5. 소셜 레이어 PRD 초안

### 5.1. 포스트(Post) 정의
*   **형태**: 텍스트(최대 500자) + 플레이리스트/트랙 카드 첨부.
*   **핵심**: 음악이 단순 링크가 아닌 플레이어 형태로 임베딩되어 피드 내에서 즉시 청취(Preview) 가능.
*   **감성 요소**: 배경색 커스텀, 무드 태그(Mood Tag) 부착.

### 5.2. 랭킹(Ranking) 시스템
*   **대상**: 플레이리스트(Curation Quality) 및 사용자(Influencer).
*   **지표**: 좋아요 수 + 저장(Save) 수 + 해당 플레이리스트를 통한 플랫폼 전환(Export) 수.
*   **주기**: 실시간 / 주간 / 역대 누적 랭킹 제공.

### 5.3. 감성 선물 (Emotional Gift)
*   **플로우**: 플레이리스트 생성 → '선물하기' 선택 → 메시지 및 디지털 카드 커스텀 → 링크 전송(카카오톡/DM).
*   **언박싱 UX**: 수신자가 링크 클릭 시, 음악이 한 곡씩 서서히 공개되며 발신자의 메시지가 등장하는 연출.
*   **BM 연동**: 프리미엄 선물 포장(유료 디자인), 실물 굿즈(LP 형태 카드) 제작 서비스로 확장.

### 5.4. MVP 컷 (Prioritization)
*   **In (P0)**: 소셜 로그인, 피드(팔로잉 기반), 좋아요, 댓글, 플레이리스트 공유.
*   **In (P1)**: 랭킹 시스템, 무드 기반 추천 피드, 감성 선물 기초 기능.
*   **Out (P2)**: 1:1 DM, 실시간 음악 감상방, 외부 SNS(X, Insta) 자동 동시 포스팅.

## 6. 우선순위 표 및 로드맵 권고

| 단계 | 목표 | 핵심 과제 | 플랫폼 |
| :--- | :--- | :--- | :--- |
| **Stage 1: Identity** | 소셜 기반 확립 | Google 인증, 피드, YTM Import, "딸깍" 가져오기 | YTM, Spotify |
| **Stage 2: Corridor** | 변환 가치 극대화 | Apple Music 확장, 쿼터 증설 기반 전면 Export | Apple Music |
| **Stage 3: Social** | 관계 및 수익화 | 감성 선물 고도화, 랭킹 시스템, 유료 선물 테마 | 전 플랫폼 |

## 7. Freeze (확정 제안 사항)
1.  **YouTube Music을 P0 플랫폼으로 확정**하고, Phase 1에서는 '가져오기 및 공유'에 집중한다.
2.  **Google OAuth를 메인 인증 수단**으로 사용하여 소셜 가입과 API 권한 획득을 일원화한다.
3.  **"가져오기 → 소셜 피드 공유"**를 최우선 UX 경로로 설정하여 사용자 유입을 극대화한다.
4.  내보내기 기능은 쿼터 상황에 맞춘 **'선택적 개방 정책'**을 유지하며 쿼터 증설을 병행한다.
