## 1. 제품 요약 (Product Summary)
AI가 생성한 데이터가 범람하는 시대에, '인간만이 생성할 수 있는 진본 데이터(Human-Authenticity)'를 수집, 검증 및 자산화하는 플랫폼입니다. 개인의 음악 취향, 감정 기록, 생활 맥락을 결합하여 고유한 가치를 지닌 '플레이리스트 에셋(PA)'을 생성하고 이를 통해 데이터 주권을 회복합니다.

## 2. 문제 정의 (Problem Statement)
*   **데이터의 저질화(Model Collapse):** AI 생성 데이터가 인터넷을 점유하면서 AI 모델 학습을 위한 '진짜 인간'의 데이터 희소성이 급증함.
*   **데이터 주권 부재:** 개인은 매일 고유한 감성 데이터를 생산하지만, 그 이익은 거대 플랫폼 기업이 독점함.
*   **신뢰의 위기:** 디지털 환경에서 무엇이 인간의 창작물이고 무엇이 AI의 결과물인지 구분하기 어려워짐.

## 3. 비전 및 원칙 (Vision and Principles)
*   **비전:** "존재하고 느끼는 것만으로도 가치가 되는 인간 중심 경제 구축"
*   **원칙:**
    1.  **진본성 우선:** AI 봇이 흉내 낼 수 없는 인간의 물리적, 생체적 맥락을 증명한다.
    2.  **사용자 주권:** 데이터의 소유권과 수익권은 생산한 개인에게 귀속된다.
    3.  **심리스한 경험:** 블록체인 기술은 배경에서 작동하며, 사용자는 일반적인 앱 사용 경험을 유지한다.

## 4. 타겟 사용자 (Target Users)
*   **Primary (데이터 생산자):** 자신의 취향과 일상을 기록하고 공유하는 것을 즐기는 MZ세대 및 크리에이터.
*   **Secondary (데이터 소비자):** 양질의 인간 학습 데이터를 필요로 하는 AI 테크 기업, 초개인화 서비스를 지향하는 스트리밍 플랫폼.

## 5. 핵심 사용자 시나리오 (Core User Scenarios)
1.  **기록 및 큐레이션:** 사용자가 특정 감정이나 상황(예: 비 오는 날의 산책)에 맞는 음악을 선택하고, 당시의 사진과 짧은 일기를 작성함.
2.  **인간 증명:** 앱은 촬영 당시의 기기 센서 데이터와 작성 패턴을 분석하여 '인간의 실제 경험'임을 백그라운드에서 검증함.
3.  **자산화:** 검증된 기록은 'PA(Playlist Asset)'라는 단위로 저장되며, 추후 거래 가능한 형태의 증서로 변환됨.
4.  **수익 창출:** 자신의 PA가 AI 학습 데이터로 채택되거나 타인에게 공유될 때 보상(포인트/토큰)을 획득함.

## 6. MVP 범위 (MVP Scope)
*   **핵심 목표:** 데이터 수집 루프 완성 및 기초적인 '인간 증명' 메커니즘 검증.
*   **범위:**
    *   음악 검색 및 플레이리스트 생성 기능 (외부 API 연동).
    *   멀티모달 기록(텍스트 일기, 사진 업로드) 기능.
    *   기초적인 기기 센서 기반 진본성 체크 (GPS, 시간대, 가속도 센서).
    *   내부 데이터베이스 기반의 자산 관리 (온체인 민팅은 선택 사항으로 유지).

## 7. 주요 기능 (Core Features)
*   **Emotional Multi-modal Logger:** 음악 + 텍스트 + 사진을 하나의 맥락으로 묶는 기록 도구.
*   **Heuristic Proof-of-Human:** 타이핑 리듬 및 센서 데이터를 활용한 초기 단계의 봇 필터링.
*   **Asset Dashboard:** 내가 생성한 PA 목록과 예상 가치/보상 확인.

## 8. 기능 요구사항 (Functional Requirements)
*   **기록 관리:** 사용자는 PA를 생성, 수정, 삭제할 수 있어야 함.
*   **음악 연동:** Spotify/YouTube Music 등 주요 스트리밍 서비스의 메타데이터와 연동되어야 함.
*   **증명 엔진:** 데이터 생성 시점의 환경 정보(Metadata)를 캡처하여 데이터와 함께 저장해야 함.

## 9. 비기능 요구사항 (Non-functional Requirements)
*   **사용성:** 지갑 생성이나 가스비 개념 없이 소셜 로그인을 통해 즉시 시작 가능해야 함.
*   **보안:** 개인의 민감한 일상 기록이므로 데이터 저장 시 암호화 필수.
*   **성능:** 대용량 이미지/영상 업로드 시에도 기록 프로세스가 끊기지 않아야 함.

## 10. 데이터 및 증명 고려사항 (Data and Proof Considerations)
*   **C2PA 활용:** 기기 레벨에서 사진의 위변조 여부 확인 시도.
*   **Keystroke Dynamics:** 일기 작성 시의 입력 패턴을 통한 인간성 추론.
*   **데이터 구조:** [음악 ID / 감정 태그 / 텍스트 / 이미지 URL / 검증 메타데이터]의 구조화된 저장.

## 11. 마켓플레이스 및 비즈니스 모델 가정
*   **C2C:** 사용자 간 취향 구매 (초기에는 포인트 기반 시스템으로 검증).
*   **C2B:** 기업용 데이터셋 판매 API 제공 (가정: 기업들이 '인간 데이터'에 프리미엄을 지불할 것이다).

## 12. 리스크 및 미결 사항 (Risks and Open Questions)
*   **[리스크] 프라이버시:** 개인의 일상 데이터와 생체 정보를 어디까지 수집/보관할 것인가? (GDPR/개인정보보호법 관련 검토 필요).
*   **[리스크] 증명 정확도:** AI 모델이 인간의 타이핑 습관이나 센서 노이즈까지 완벽히 흉내 낼 경우의 방어책.
*   **[미결]** 웨어러블 기기(스마트워치) 연동의 기술적 난이도 및 보급률 문제.
*   **[미결]** 법적 규제 하에서 '데이터 판매' 행위의 적법성 확인.

## 13. 성공 지표 (Success Metrics)
*   **Retention:** 사용자가 주간 3회 이상 PA를 생성하는가?
*   **Data Quality:** 수집된 데이터 중 '인간 진본'으로 분류된 데이터의 비율.
*   **Engagement:** 생성된 PA가 다른 사용자에게 공유되거나 '좋아요'를 받는 횟수.

## 14. Post-MVP
*   **Full On-chain Minting:** L2 솔루션을 활용한 저비용 NFT화.
*   **ZK-Proof Privacy:** 영지식 증명을 도입하여 민감 정보를 노출하지 않고 진본성만 증명하는 기능.
*   **Wearable Sync:** 실시간 심박수 등 생체 데이터 기반의 '공명 증명(Proof of Resonance)' 구현.
*   **B2B Dashboard:** AI 기업들이 필요한 데이터를 필터링하고 구매할 수 있는 마켓플레이스 프론트엔드 구축.
