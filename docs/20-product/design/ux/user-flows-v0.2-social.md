## 0. 버전 변경 범위

이 문서는 `user-flows-v0.1.md`를 **대체하지 않는다.** Flow A–D와 기존 9개 라우트는 그대로 유지된다. 본 문서는 다음만 추가·정의한다:

- **Flow E:** 원클릭 변환 (붙여넣기→목적지→진행→완료)
- **Flow F:** 피드 (포스트 작성 / 소비 / 상호작용)
- **Flow G:** 선물 (보내기 / 받기 / 언박싱)
- **Flow H:** 랭킹 탐색 → 자산 상세 → 변환/저장 전환
- **신규 라우트 인벤토리** (기존 라우트와 비충돌)
- **각 화면 4-상태 정의** (empty / loading / failure / success)

## 2. Flow E — 원클릭 변환

### 2.1 목표

"딸깍 한 번으로 플레이리스트를 옮긴다"는 사용자 인식을 만든다. 재사용 시 3스텝으로 완료되어야 한다.

### 2.2 진입점

- 랜딩(`/`) 히어로 CTA: "링크 붙여넣기로 시작" (accent 버튼)
- 헤더 네비게이션: "변환" 글로벌 링크 (로그인 여부 무관)
- 라이브러리(`/assets`)의 "빠른 변환" floating 버튼
- 모바일 공유 시트에서 `/convert`를 타깃으로 지정 (P1)

### 2.3 Step-by-step

**E-1. 변환 진입 (`/convert`)**

화면 구성:
- 상단: "플레이리스트를 어디로 옮길까요?" (h2, text-hi)
- 중앙: URL 입력 영역 — 큰 input (surface-2, radius 14px, hairline 보더)
  - placeholder: "Spotify 또는 Apple Music 링크를 붙여넣으세요"
  - 붙여넣기 감지 시 자동 파싱 시작 (debounce 300ms)
  - 파싱 성공: 앨범아트 + 제목 + 트랙 수 프리뷰 카드 즉시 표시
  - 파싱 실패: 인라인 에러 "올바른 플레이리스트 링크가 아니에요"
- 하단: 최근 변환 이력 (로그인 상태일 때만, 최대 3개 표시)
- 소스 플랫폼 자동 감지 (Spotify 도메인 → Spotify 뱃지, Apple Music 도메인 → Apple 뱃지)

인증 처리:
- 비로그인 상태: 링크 파싱까지 허용 → 목적지 선택 화면에서 처음 인증 요청
- 로그인+미연결 상태: 소스 플랫폼 OAuth 요청은 플레이리스트 정보 fetch 시점에 lazy 발동

**E-2. 목적지 선택 및 확인 (`/convert` — 인라인 스텝)**

URL 파싱 성공 후 동일 화면에서 하단으로 슬라이드업:
- 파싱된 자산 프리뷰 카드 (커버 64px + 제목 + 트랙 수 + 소스 플랫폼 배지)
- "어디로 보낼까요?" 목적지 선택
  - MVP는 단일 선택지: "Apple Music으로 변환" (accent 버튼)
  - Apple Music 미연결 시: 버튼 옆에 "연결 필요" 경량 뱃지 → 클릭 시 MusicKit 모달
  - Apple Music 연결 시: 버튼 바로 클릭 가능 ("딸깍")
- "시작하기" 클릭 → `/convert/progress`로 이동

**E-3. 변환 진행 (`/convert/progress`)**

화면 구성 (Nocturne ProgressNarrative 패턴 적용):
- 중앙: 소스 플레이리스트 커버 (대형, 160px, cover-glow 펄스)
- 커버 아래: ProgressNarrative 문장 (accent 텍스트, cycle)
  - "트랙 정보를 모으는 중이에요"
  - "ISRC 기준으로 정규화하는 중이에요"
  - "Apple Music에서 트랙을 찾는 중이에요"
  - "플레이리스트를 만들고 있어요"
- 하단: accent 슬림 진행 바 (글로우 포함)
- 변환 중 "백그라운드에서 계속" 링크 (ghost, text-mid) — 클릭 시 `/feed` 또는 `/assets`로 이동, 완료 시 Toast 알림

백그라운드 처리:
- 사용자가 화면을 이탈해도 변환 작업은 서버에서 계속 진행
- 완료 시 Toast: "변환이 완료됐어요 — 확인하기" → `/convert/result`로 딥링크

**E-4. 변환 완료 + 자산화 초대 (`/convert/result`)**

성공 상태:
```
[커버 이미지 — 대형, cover-glow]
 ✓ [n]곡이 Apple Music으로 옮겨졌어요   ← success 토큰 색상
 [플레이리스트 제목]
 [Apple Music에서 열기] ← accent primary 버튼
 
 ─────────────────────────────
 이 플레이리스트에 이름을 붙여두시겠어요?   ← 자산화 초대
 [제목 입력] [감정 태그 선택] [한 줄 메모]
 [자산으로 저장] ← accent secondary
 [나중에 하기] ← ghost, text-mid
 ─────────────────────────────
 
 [n곡 중 m곡 변환됨]
 ▼ [매칭 안 된 k곡 보기] ← accordion 기본 접힘
```

매칭 실패 accordion 펼침:
- 실패 트랙 목록 (TrackRow + `--danger` MatchConfidenceBadge)
- 각 트랙: "대체 후보 보기" ghost 버튼 → 모달로 처리
- "나중에 해결하기" 링크 → `/assets/[id]` 로 라우팅

자산화 초대 처리:
- 사용자가 제목/태그/메모 입력 후 "자산으로 저장" → PA 생성 + `/assets/[id]` 이동
- "나중에 하기" 클릭 → 이름 없는 PA가 Draft로 저장됨 + `/assets` 이동 + Toast "초안이 저장됐어요"

### 2.4 분기와 예외

| 상황 | 처리 |
|:---|:---|
| 소스 플랫폼 OAuth 거부 | 인라인 에러 + "다시 연결하기" CTA, 링크 파싱 프리뷰 유지 |
| Apple Music 미구독 계정 | 변환 전 "Apple Music 구독이 필요해요" 안내 — 변환 차단 |
| 빈 플레이리스트 | 파싱 단계에서 "곡이 없는 플레이리스트예요" 에러 — 변환 시작 막음 |
| 전체 매칭 실패 | `failure` 상태 화면 + "이 플레이리스트는 Apple Music에서 찾을 수 없는 곡들이에요" |
| 네트워크 단절 | Toast "연결이 끊겼어요" + 자동 재시도 3회 → 실패 시 수동 재시도 CTA |

### 2.5 화면 4-상태 정의

**`/convert`**
- `empty`: URL 입력 필드 빈 상태. placeholder 텍스트 표시. 최근 이력 없음.
- `loading`: 링크 파싱 중. 입력 필드 내 spinner dot 3개 (Nocturne: accent 색상).
- `failure`: 파싱 실패. 입력 필드 `--danger` 보더 + 인라인 에러 메시지.
- `success`: 프리뷰 카드 슬라이드업 + 목적지 선택 CTA 표시.

**`/convert/progress`**
- `loading` (단일 상태): ProgressNarrative cycling + accent 진행 바.

**`/convert/result`**
- `empty`: 변환 결과 없음 (도달할 수 없는 상태 — redirect로 처리).
- `loading`: 결과 집계 중. 커버 + "집계 중이에요" ProgressNarrative.
- `failure`: 전체 변환 실패. `--danger` 히어로 + 사유 + 재시도 CTA.
- `success`: 완료 히어로 + 자산화 초대 섹션 + 매칭 실패 accordion.

## 3. Flow F — 피드

### 3.1 목표

사용자가 자신의 플레이리스트 자산에 감성 서사를 붙인 "포스트"를 작성하고, 타인의 포스트를 발견·공감·저장할 수 있다.

### 3.2 피드 진입 (`/feed`)

**레이아웃:**
- 모바일 우선: 단일 컬럼, 카드 간격 16px
- 상단: 탭 네비게이션 "전체 | 팔로잉" (surface-2, 선택 탭은 accent 언더라인)
- 피드 상단 고정: "포스트 작성" 입력창 프리뷰 (surface-2, radius 14px)
  - 아바타 32px + placeholder "오늘의 플레이리스트를 공유해보세요"
  - 클릭 시 작성 모달/페이지로 확장

**피드 카드 목록:**
- 무한 스크롤, 페이지당 20개 로드
- 각 카드: `social-ux-research-v0.1.md §2.6` 포스트 카드 anatomy 적용
- 카드 호버(데스크톱): `-translate-y-1` + hairline-strong 보더 (Nocturne Card 패턴)

### 3.3 포스트 작성 플로우

**F-1. 작성 진입**

- 피드 상단 프리뷰 클릭 → 모달 오버레이 (glass, blur 18px, 최대 너비 600px)
- 또는 `/assets/[id]`의 "피드에 공유" 버튼 → 자산 첨부된 채로 작성 모달 열림

**F-2. 모달 내 작성 화면**

```
[아바타 32px] @handle
─────────────────────────────────────────────
[텍스트 입력 — 자동 확장, 최소 88px, 최대 320px]
placeholder: "이 플레이리스트는..."
─────────────────────────────────────────────
[첨부된 자산 카드 — AssetCard, 있는 경우]
 커버 64px | 제목 | 트랙 수 | 태그
 [×] 제거 버튼 (우상단)
─────────────────────────────────────────────
하단 툴바:
[🎵 자산 첨부] [🏷 태그]   [게시] ← accent primary 버튼
```

**자산 첨부:**
- 라이브러리 내 자산 검색/선택 모달 (cover-glow 카드 그리드)
- 또는 `/convert` 링크 입력 → 즉석 변환 후 첨부 (자산화 초대 스킵, 포스트 첨부 우선)
- 플레이리스트 또는 단일 트랙 모두 가능

**게시 처리:**
- 텍스트만 (최소 1자) 또는 텍스트+자산 — 자산만 단독 첨부 불가
- "게시" 클릭 → 모달 닫힘 + 피드 상단에 새 카드 낙하 (spring 300ms)
- 실패 시 입력 내용 보존 + Toast "게시에 실패했어요. 다시 시도할까요?"

**F-3. 포스트 소비 (`/p/[postId]`)**

- 피드 카드 클릭 → `/p/[postId]`로 라우팅 (또는 모바일에서 바텀 시트)
- 포스트 상세: 피드 카드 anatomy 확장 버전
  - 본문 전문 (줄임 없음)
  - 첨부 자산 카드 (트랙 리스트 접기/펼치기 포함)
  - 댓글 목록 + 입력창

**댓글 입력:**
- 입력창은 화면 하단 고정 (모바일 sticky)
- 제출 시 낙관적 업데이트 (UI 먼저 추가, 서버 확인 후 확정)

**F-4. 상호작용**

| 액션 | 인터랙션 | 서버 동작 |
|:---|:---|:---|
| ♡ 좋아요 | 탭 시 accent fill + 카운트 +1 (낙관적) | `POST /posts/:id/likes` |
| 💬 댓글 | 댓글 입력창 포커스 | `POST /posts/:id/comments` |
| ↗ 공유 | 시스템 공유 시트 (URL: `/p/[postId]`) | 없음 |
| 🔖 저장 | accent fill + "내 라이브러리에 자산 복사 확인" 토스트 | `POST /assets` (복사) |
| 팔로우 | `/u/[handle]`의 팔로우 버튼 또는 카드 내 팔로우 | `POST /users/:handle/follow` |

### 3.4 화면 4-상태 정의

**`/feed`**
- `empty`: 팔로잉 탭에서 팔로우한 사람이 없을 때. "아직 팔로우한 사람이 없어요" + 추천 사용자 카드 3개.
- `loading`: 스켈레톤 카드 3개 (surface-2, shimmer 애니메이션, Nocturne 색상).
- `failure`: "피드를 불러오지 못했어요" + 새로고침 버튼 (accent ghost).
- `success`: 포스트 카드 목록 + 무한 스크롤.

**`/p/[postId]`**
- `empty`: 존재하지 않는 postId. "이 포스트는 없어요" + 피드로 돌아가기.
- `loading`: 포스트 상세 스켈레톤 (헤더 + 본문 2줄 + 자산 카드 placeholder).
- `failure`: "포스트를 불러오지 못했어요" + 재시도 CTA.
- `success`: 포스트 전문 + 댓글 목록.

**포스트 작성 모달**
- `empty`: 텍스트 비어있음. "게시" 버튼 비활성화 (opacity 0.4).
- `loading`: 게시 중. "게시" 버튼 내 spinner dot.
- `failure`: 모달 유지 + Toast 에러.
- `success`: 모달 닫힘 + 피드 상단 낙하 애니메이션.

## 4. Flow G — 선물

### 4.1 목표

자산을 감성 선물로 포장해 특정인에게 전달한다. 수신자는 언박싱 연출을 통해 받는다.

### 4.2 선물 발신 플로우 (`/gift/send`)

**G-1. 발신 진입**

진입점:
- `/assets/[id]`의 "선물하기" 버튼 → 해당 자산 첨부 채로 진입
- `/gift/send` 직접 진입 → 자산 선택 먼저

**G-2. 선물 구성 화면 (`/gift/send`)**

단계형 카드 UI (한 화면에서 step indicator 없이 자연스럽게 아래로 전개):

```
── 1. 선물할 자산 ──────────────────────────────
[AssetCard 미리보기]   [변경] ghost 버튼
────────────────────────────────────────────────

── 2. 포장 스킨 선택 ───────────────────────────
[Ink]  [Amber]  [Indigo]   ← 가로 스크롤 칩
 ↑ 선택 시 카드 배경 즉시 반영
────────────────────────────────────────────────

── 3. 편지 카드 ────────────────────────────────
textarea: "이 음악을 보내는 이유 (선택, 최대 200자)"
placeholder: "이 곡들이 생각나서 보내요."
글자 수 카운터: [현재/200] text-low 우하단
────────────────────────────────────────────────

── 4. 수신자 지정 ──────────────────────────────
[앱 내 @handle 검색] 또는 [링크로 공유]
 • @handle 검색: 자동완성 드롭다운 (surface-3, glass)
 • 링크 공유: /gift/[token] URL 생성 → 시스템 공유 시트
────────────────────────────────────────────────

[선물 보내기] ← accent primary, 하단 고정 (모바일)
```

**G-3. 발송 처리**

- "선물 보내기" 클릭 → `/gift/[token]` URL 생성 + 수신자 알림 발송
- 발신자 화면: Toast "선물을 보냈어요 — 링크 복사" + 링크 미리보기 카드
- `/assets/[id]`로 복귀

---

### 4.3 선물 수신 플로우 (`/gift/[token]`)

**G-4. 봉투 화면 (언박싱 전)**

- 비로그인 접근 허용
- 화면 전체를 cover-glow 블러 처리 (자산 커버 이미지를 배경으로, opacity 0.4 + blur 30px)
- 중앙 봉투 카드 (glass, 대형):
  ```
  [발신자 아바타 48px]
  [발신자 @handle]이/가 플레이리스트 선물을 보냈어요
  
  [자산 제목] ← 블러 처리 (hover 시 잠깐 해제 → 호기심 유발)
  
  [열어보기] ← accent primary, 펄스 글로우 애니메이션
  ```
- 하단: "선물 유효 기간 N일 남음" (label, text-low)

**G-5. 언박싱 애니메이션**

"열어보기" 클릭 시 순서:
1. 봉투 카드 상단 뚜껑이 펼쳐지는 CSS 애니메이션 (rotateX, 400ms, ease-out)
2. 커버 이미지 슬라이드업 (translateY -60px, fade-in, spring 350ms)
3. 편지 텍스트 fade-in (300ms delay 50ms stagger)
4. 트랙 리스트 순차 등장 (stagger 60ms per row)
5. 액션 버튼 등장 (fade+rise 마지막)

언박싱 후 화면 구성:
```
[커버 이미지 — 대형, cover-glow, 전체 너비]

[발신자 @handle]이/가 보낸 선물
[자산 제목] ← h2

[편지 텍스트] ← body, text, line 1.6, 이탤릭 아님 (Nocturne 원칙: 세리프 금지)

[감정 태그 칩들]

[트랙 리스트 — 최대 5개 표시, 나머지 접기]

──────────────────────────────────
[✓ 내 라이브러리에 저장] ← accent primary
[나중에 받기] ← ghost, text-mid
[조용히 거절] ← text-low, 작게
```

**G-6. 수락/거절 처리**

- **수락 ("내 라이브러리에 저장"):**
  - 로그인 상태: 자산이 복사되어 `/assets/[id]` 로 라우팅 + Toast "저장됐어요"
  - 비로그인 상태: "저장하려면 로그인이 필요해요" → 로그인 후 자동 수락 처리 (redirect_after_auth 파라미터)
- **나중에 받기:** 링크 북마크 유지 + Toast "이 링크에서 언제든 다시 열 수 있어요 (N일까지)"
- **조용히 거절:** 발신자에게 알림 없음. `/gift/[token]` 는 "이미 수락되거나 만료된 선물이에요" 상태로 전환.

---

### 4.4 화면 4-상태 정의

**`/gift/send`**
- `empty`: 자산 미선택. "선물보내기" 버튼 비활성화.
- `loading`: 발송 중. 버튼 내 spinner.
- `failure`: "선물 발송에 실패했어요" Toast + 입력 유지.
- `success`: Toast + 링크 카드 + `/assets/[id]` 복귀.

**`/gift/[token]` — 봉투 화면**
- `empty`: 도달 불가 (모든 토큰은 존재하거나 만료).
- `loading`: 봉투 카드 스켈레톤 (glass + shimmer).
- `failure`: "유효하지 않거나 만료된 선물이에요" + 홈 CTA.
- `success`: 봉투 화면 (언박싱 전).

**`/gift/[token]` — 언박싱 후**
- `loading`: 언박싱 애니메이션 진행 중 (입력 비활성화).
- `success`: 언박싱 완료 화면 + 수락/거절 버튼.

## 5. Flow H — 랭킹 탐색

### 5.1 목표

랭킹이 "차트"가 아닌 "발견 피드"처럼 느껴진다. 탐색 → 자산 상세 → 변환/저장이 한 흐름으로 연결된다.

### 5.2 랭킹 탐색 (`/ranking`)

**레이아웃:**

```
[헤더] 랭킹   [이번 주 ▾] ← 기간 필터 ghost 드롭다운

[감정 태그 필터 — 가로 스크롤 칩]
 [전체] [#비오는날] [#퇴근길] [#집중] [#위로] [#파티] …
 선택: accent-soft bg + accent text (EmotionTagPicker)

──────────────────────────────────────────────────────

[1위 자산 — 히어로 카드]
┌────────────────────────────────────────────────────┐
│  [커버 이미지 — 전체 너비, cover-glow, 비율 16:9]  │
│  [대형 순위 숫자 — num 8rem, text-low, 좌하단]     │
│  [자산 제목 h2] · [@handle sm] · [트랙 N개 sm]     │
│  [감정 태그 칩들]                                  │
│  [▲ 12] ← 순위 변동 (success), NEW 표시 (accent)  │
│  [저장 🔖] [변환 ⇄] ← 우하단 액션 버튼           │
└────────────────────────────────────────────────────┘

[2–20위 — 컴팩트 카드 리스트]
┌───┬──────┬─────────────────────────────┬────────┐
│ 2 │[커버]│ 자산 제목 (h3)              │ [🔖⇄] │
│   │ 48px │ @handle · 태그              │        │
├───┼──────┼─────────────────────────────┼────────┤
│ 3 │[커버]│ 자산 제목                   │ [🔖⇄] │
…

[더 보기 — 21위 이하 페이지네이션]
```

**순위 변동 인디케이터:**
- `↑ N` : success 색상 + 위 화살표
- `↓ N` : danger 색상 + 아래 화살표
- `NEW` : accent-soft bg + accent 텍스트 pill
- 변동 없음 : 표시 안 함 (text-low)

### 5.3 랭킹 → 자산 상세 (`/assets/[id]`)

- 랭킹 카드 클릭 → `/assets/[id]` (기존 라우트)
- 자산 작성자가 아닌 사람의 진입: 읽기 전용 뷰 (편집 UI 숨김)
- 추가 CTA (기존 Flow D "감상 페이지" 개념 확장):
  - "내 라이브러리에 저장" → 자산 복사 + Toast
  - "이걸로 변환" → `/convert`에 해당 자산 링크 pre-fill 채로 진입

### 5.4 랭킹 → 즉시 변환 (`/convert` pre-fill)

- 랭킹 카드의 "변환 ⇄" 버튼 클릭 → `/convert?source=[assetId]`
- `/convert` 진입 시 해당 자산이 파싱 결과 프리뷰 카드로 즉시 표시
- 목적지 선택 → 변환 시작 (E-2 이후 동일 플로우)

### 5.5 화면 4-상태 정의

**`/ranking`**
- `empty`: 선택한 감정 태그에 해당하는 자산이 없음. "이 태그로 자산을 만들어보세요" + 피드 작성 CTA.
- `loading`: 히어로 카드 스켈레톤 (surface-2 + shimmer) + 컴팩트 리스트 스켈레톤 5개.
- `failure`: "랭킹을 불러오지 못했어요" + 새로고침 CTA.
- `success`: 히어로 1위 + 2–20위 리스트.

## 6. 사용자 프로필 (`/u/[handle]`)

### 6.1 목적

Flow F/H에서 자연스럽게 진입되는 사용자 발견 허브. 팔로우 관계 형성의 핵심 접점.

### 6.2 화면 구성

```
[커버 배너 — 사용자가 설정한 배경 또는 최근 자산 커버 글로우]

[아바타 80px] @handle
[표시명 h2]
[자기소개 body, text-mid, 최대 2줄]
[자산 N개] · [팔로워 N] · [팔로잉 N]
[팔로우 / 팔로잉] ← accent primary / ghost (상태에 따라)

──────────────────────────────────────────────────────
[탭] 자산 | 포스트
──────────────────────────────────────────────────────
[자산 탭] AssetCard 그리드 (2컬럼, 모바일 기준)
[포스트 탭] 포스트 카드 목록 (단일 컬럼)
```

### 6.3 화면 4-상태 정의

**`/u/[handle]`**
- `empty`: 해당 handle 존재하지 않음. "이 사용자는 없어요" + 랭킹/피드 CTA.
- `loading`: 프로필 헤더 스켈레톤 + 자산 그리드 스켈레톤 4개.
- `failure`: "프로필을 불러오지 못했어요" + 재시도 CTA.
- `success`: 전체 프로필 + 탭 콘텐츠.

**자산 탭 empty:**
- 자신의 프로필: "첫 자산을 만들어보세요" + accent CTA "Spotify에서 가져오기"
- 타인의 프로필: "아직 공개된 자산이 없어요"

**포스트 탭 empty:**
- 자신의 프로필: "첫 포스트를 작성해보세요" + 작성 모달 CTA
- 타인의 프로필: "아직 포스트가 없어요"

## 7. 전체 플로우 상호작용 맵

```
/                       랜딩
├──→ /convert           E: 원클릭 변환 진입
│    ├──→ /convert/progress
│    └──→ /convert/result ──→ /assets/[id] (자산화 완료 시)
│
├──→ /import            A: Spotify OAuth 진입 (기존)
│    └──→ /import/[id]/progress ──→ /assets/[id]
│
├──→ /assets            라이브러리
│    └──→ /assets/[id]  자산 상세
│         ├──→ /assets/[id]/export ──→ result
│         ├──→ /gift/send          G: 선물 발신
│         └──→ /p/[postId] 공유 시 포스트 작성 모달
│
├──→ /feed              F: 소셜 피드
│    └──→ /p/[postId]   포스트 상세
│         └──→ /u/[handle]
│
├──→ /ranking           H: 랭킹 탐색
│    ├──→ /assets/[id]  자산 상세 (읽기 전용)
│    │    └──→ /convert (변환 CTA pre-fill)
│    └──→ /u/[handle]
│
├──→ /gift/send         G: 선물 발신
│
├──→ /gift/[token]      G: 선물 수신 (비로그인 OK)
│    └──→ /assets/[id] (수락 시)
│
├──→ /u/[handle]        프로필
│    ├──→ /assets/[id]
│    └──→ /p/[postId]
│
└──→ /share/[token]     D: 감상 페이지 (기존, 비로그인 OK)
```

## 8. 모바일 우선 고려사항

모든 신규 화면은 375px 기준 단일 컬럼으로 설계한다.

| 컴포넌트 | 모바일 처리 |
|:---|:---|
| 포스트 작성 모달 | 화면 전체 시트 (바텀 시트 → 풀 화면으로 전환) |
| 랭킹 감정 태그 필터 | 가로 스크롤 칩, 스냅 포인트 |
| 선물 수신 언박싱 | 세로 전체 화면 (9:16 비율 최적화) |
| AssetCard 임베드 (피드) | 커버 64px 고정, 가로 레이아웃 유지 |
| 댓글 입력창 | 키보드 위 sticky (iOS safe area 포함) |
| 변환 진행 화면 | 커버 120px (대형 줄임), 텍스트 중앙 정렬 |
