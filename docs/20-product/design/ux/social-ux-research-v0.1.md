## 0. 리서치 목적과 범위

이 문서는 4개 영역의 벤치마크를 분석하고, plshare2 맥락에서 차용·제거할 패턴을 도출한다.

## 1. 벤치마크 A — 원클릭 전환 UX

### 1.1 TuneMyMusic

**플로우 분석**

| 단계 | 화면 | 마찰 지점 |
|:---|:---|:---|
| 1 | 소스 플랫폼 선택 | 아이콘 그리드, 한 번 클릭 |
| 2 | 소스 인증 (OAuth) | 처음 1회만 발생. 이미 연결 시 스킵 |
| 3 | 플레이리스트 선택 | 리스트 또는 URL 붙여넣기 |
| 4 | 목적지 플랫폼 선택 | 동일 아이콘 그리드 |
| 5 | 목적지 인증 (OAuth) | 2번째 플랫폼도 처음 1회 |
| 6 | 변환 시작 | 한 클릭 — 진행 바 표시 |
| 7 | 결과 | 성공/누락 트랙 요약 |

**총 스텝 (최초 사용):** 7스텝 / **재사용:** 3스텝 (3→4→6)
**인증 마찰 흡수:** lazy auth — 각 플랫폼의 실제 연결 시점까지 인증을 미룬다. 첫 변환 전에 양쪽을 동시에 요구하지 않는다.
**매칭 실패 노출:** 변환 완료 후 summary에서 "X곡 추가 실패" 를 숫자로만 표시. 개별 실패 트랙 목록을 fold/expand로 숨긴다.

**차용할 것:**
- 재사용 시 3스텝으로 압축되는 구조 — plshare2의 "딸깍" 목표와 정확히 부합
- URL 직접 붙여넣기를 보조 진입 경로로 병행 제공 (기존 Flow A-3과 일치)
- 변환 완료 후 실패 summary를 숫자+fold 형태로 — 매칭 실패를 "작업 중단"이 아닌 "정보"로 처리

**피할 것:**
- 소스/목적지 선택 화면이 동일한 아이콘 그리드 2회 반복 — plshare2는 현재 Spotify↔Apple Music 비대칭 브릿지만 지원하므로 불필요한 플랫폼 선택 단계가 없다
- 변환 결과 후 재구매 upsell 모달 즉시 노출 — 감성 자산화 맥락 단절

### 1.2 Soundiiz

**플로우 분석**

| 단계 | 화면 | 마찰 지점 |
|:---|:---|:---|
| 1 | 회원가입/로그인 (이메일) | **첫 진입 필수** — 전환 전에 계정 생성 강제 |
| 2 | 소스 플랫폼 연결 | 대시보드에서 각 서비스 connect |
| 3 | 플레이리스트 선택 | 좌측 패널 |
| 4 | 우측 패널에서 목적지 선택 | 드래그앤드롭 또는 "Convert" 버튼 |
| 5 | 변환 진행 | 프리미엄 플랜은 즉시, 무료는 100곡 제한 |

**총 스텝 (최초):** 5스텝이지만 사전 계정 생성 장벽이 크다.
**인증 마찰 흡수:** 가장 전통적인 방식 — 전환 전에 모든 인증 완료를 요구한다.
**매칭 실패 노출:** 실패 트랙을 행 단위로 빨간 하이라이트로 즉시 노출. 밀도가 높아 피로함.

**차용할 것:**
- 좌우 패널 레이아웃(소스 | 목적지)으로 비교 가시성 확보 — export 미리보기 화면에 참고
- 플랜 구분 없이 첫 변환을 풀로 경험하게 하는 신뢰 구축 전략

**피할 것:**
- 전환 전 계정 가입 강제 — 신규 사용자 이탈 최대 지점
- 매칭 실패를 행 단위로 전면 노출 — 인지 부하 과다. plshare2는 MatchConfidenceBadge + fold/summary 유지

**매칭 실패 노출:** "X곡 이전 불가" 알림 배지 — 경량하고 비차단적. 상세는 탭으로 분리.

**차용할 것:**

**피할 것:**
- 네이티브 앱 설치 장벽 — plshare2는 웹 우선
- 양쪽 플랫폼 동시 연결 대시보드 — 불필요한 인지 부하

### 1.4 SongShift (iOS 전용)

**플로우 분석**

| 단계 | 화면 | 마찰 지점 |
|:---|:---|:---|
| 1 | 소스 플레이리스트 선택 | iOS 공유 시트에서 직접 진입 가능 |
| 2 | 목적지 선택 | 한 화면 |
| 3 | 변환 | 즉시 |

- 재사용 3스텝 목표 달성 레퍼런스

**피할 것:**
- iOS 전용 아키텍처 — plshare2는 웹 + PWA 우선

### 1.5 원클릭 전환 플로우 설계 권고

#### 목표 플로우 (재사용 시 3스텝)

```
[현행 Flow A — 7스텝]
① 랜딩 진입
② Spotify OAuth (필수 선행)
③ /import — 플레이리스트 선택
④ /import/[id]/progress — 임포트 진행
⑤ /assets/[id] — 자산 상세 (감성 맥락 작성)
⑥ /assets/[id]/export — 내보내기 미리보기
⑦ /assets/[id]/export/result — 결과

[목표 Flow E — 붙여넣기 진입 시 3스텝 (재사용)]
① /convert — 링크 붙여넣기 (or 라이브러리에서 자산 선택)
② 목적지 확인 (Apple Music, 연결 이미 됐으면 자동 스킵)
③ 변환 진행 → 결과
```

#### 인증 마찰 흡수 전략 — Lazy Auth 권고

plshare2는 다음 순서로 인증을 흡수한다:

1. **소스 인증 (Spotify):** `/convert` 화면 또는 `/import`에서 플레이리스트를 선택하려는 순간에 요청. 링크 붙여넣기 경로에서는 붙여넣기 후 파싱 시도 후 인증 요청.
2. **목적지 인증 (Apple Music):** "변환 시작" CTA를 클릭하는 순간까지 최대한 미룬다. MusicKit 모달은 변환 직전 1회만.
3. **plshare2 계정:** Spotify OAuth 콜백으로 암묵적 계정 생성(소셜 로그인). 별도 회원가입 폼 없음.

원칙: **"작업을 시작한 후에야 권한을 요청한다."** 사용자가 이미 목적지를 정한 시점에서 인증 요청이 오면 완료 동기가 생긴다.

#### 매칭 실패 노출 방식 — 현행 원칙 유지 + 개선

기존 `MatchConfidenceBadge` 패턴은 유지하되 다음을 추가:
- 변환 결과 화면 최상단에 "X곡 중 Y곡 전환됨" 숫자 요약 (대형, num 토큰)
- 실패 목록은 `접기/펼치기` accordion — 기본값 접힘
- "나중에 해결" CTA를 명시 — 지금 당장 해결을 강제하지 않음

#### Emotional Context 자산화 단계 배치 — 권고: 변환 후 선택 배치 (Option B)

두 가지 안을 비교한다:

**Option A — 변환 중간 삽입 (3스텝 안에 자산화 포함)**

```
붙여넣기 → 목적지 확인 → [감정 태그 + 한 줄 메모 선택 입력] → 변환 → 결과
```

- 장점: 자산화가 변환 경험의 일부가 되어 자연스럽게 Context Density 향상
- 단점: "딸깍"이라는 속도 목표와 충돌. 원클릭 전환을 원하는 사용자는 이 단계를 "방해물"로 인식. A/B 테스트 전 채택 부적합.

**Option B — 변환 완료 후 선택 단계 배치 (권고)**

```
붙여넣기 → 목적지 확인 → 변환 시작 → [변환 진행 중] → 결과 화면
                                                          ↓
                                            "이 전환에 이름을 붙여두세요" (선택, 5초 skip 가능)
                                            → 감정 태그 + 제목 + 한 줄 메모 경량 입력
                                            → 자산으로 저장 완료
```

- 장점: 변환 완료의 달성감이 있는 상태에서 자산화 초대 → 수용률 ↑. 딸깍 속도는 보장.
- 단점: 원클릭만 원하는 사용자가 skip하면 Context Density 하락.
- 대응: skip한 자산도 나중에 `/assets/[id]`에서 언제든 자산화 가능. "나중에 하기" 옵션 명시.

**권고: Option B 채택.** 변환 속도를 핵심 가치로 먼저 전달하고, 자산화는 변환 달성감 위에서 제안한다. "딸깍 후 감동"이 자산화 수용률을 높인다.

## 2. 벤치마크 B — 음악×소셜 피드

### 2.1 SoundCloud — 파형 위 타임드 댓글

**핵심 패턴:** 재생 바의 특정 시간 지점에 댓글이 부착된다. 음악이 재생될 때 댓글이 파형 위를 흐른다.

**차용할 것:**
- "특정 트랙에 대한 감상을 남기는" 행위 자체의 콘텐츠 가치 — plshare2 포스트 카드에서 특정 트랙에 텍스트를 달 수 있는 "트랙 주석" 기능 (P1)
- 파형 자체보다 "음악 + 사람의 말"의 동시 소비 경험 원칙

**피할 것:**
- 실시간 파형 렌더링 — 라이선스 없는 음원 재생 금지 원칙 위반. plshare2는 Player-Agnostic이므로 파형 자체는 불필요
- 댓글이 재생 타임라인에 종속되는 구조 — 재생 없이 소비하는 피드 콘텐츠 맥락에 부적합

---

### 2.2 Airbuds — 친구 청취 피드

**핵심 패턴:** 친구가 지금 무엇을 듣고 있는지 실시간으로 피드에 표시. 이름+앨범아트+트랙명의 미니멀 카드.

**차용할 것:**
- "친구의 음악 활동"을 피드 콘텐츠로 만드는 개념 — plshare2에서는 실시간 대신 "자산 공개" 이벤트를 피드에 노출
- 앨범아트 중심의 초소형 카드 — 피드에서 스크롤 시 커버가 먼저 눈에 들어오는 구조

**피할 것:**
- 실시간 청취 상태 노출 — 개인정보 민감도 높음. plshare2는 사용자가 명시적으로 공개한 자산만 피드에 등장
- 친구 관계 그래프 기반 — MVP에서는 follow/unfollow 단방향 팔로우로 단순화

---

### 2.3 Spotify Blend / Jam

**핵심 패턴:** 두 사람의 취향을 섞어 공동 플레이리스트를 생성. 취향 교집합 시각화(파이 차트 형태).

**차용할 것:**
- "나의 자산 + 상대방 자산" 교집합 시각화 — 선물 받기 플로우에서 "우리의 겹치는 취향" 표시 (P2)
- 초대 링크로 공동 경험 진입 — /gift/[token] 링크 공유와 동일 패턴

**피할 것:**
- 취향 계산 결과에 과도한 중점 — plshare2의 핵심은 인간적 서사(일기/감정태그)이지 알고리즘 매칭이 아님

---

### 2.4 Instagram Notes — 음악 연동

**핵심 패턴:** 프로필 상단 14자 메모에 음악을 첨부. 팔로워 피드에 메모+음악이 미니 카드로 노출.

**차용할 것:**
- 짧은 텍스트 + 음악이 하나의 원자적 콘텐츠 단위가 되는 개념 — plshare2 포스트의 최소 단위: 텍스트(최소 1자) + 자산 첨부
- 팔로워 피드에 자연스럽게 등장 — push 알림 없이 피드 소비로 발견

**피할 것:**
- 14자 글자 수 제한 — plshare2 포스트는 긴 감성 서사를 지원해야 함 (일기 수준)
- 기능이 인스타그램 UI의 일부로 숨어있는 구조 — plshare2는 포스트 작성이 1급 액션

### 2.5 X(구 트위터) — 음악 카드

**핵심 패턴:** Apple Music/Spotify 링크 붙여넣기 시 앨범아트+제목+아티스트+재생 버튼이 임베드 카드로 전개.

**차용할 것:**
- 링크 → 리치 카드 자동 전개 — plshare2에서 자산 링크를 피드에 첨부하면 AssetCard로 전개
- 외부 링크가 아닌 플랫폼 내 카드로 소비 — 이탈 최소화

**피할 것:**
- 재생 프리뷰 버튼 — plshare2는 앱 내 재생 없음. 대신 "외부에서 열기" 딥링크로 대체

### 2.6 포스트 카드 Anatomy (plshare2 설계안)

포스트 = "글 + 음악 자산 첨부"의 복합 콘텐츠 단위. 아래 구조를 기준으로 한다.

```
┌─────────────────────────────────────────────┐
│ [Avatar 32px] @handle · 3시간 전   [•••]   │  ← 작성자 행 (surface-1 상단)
├─────────────────────────────────────────────┤
│                                             │
│  포스트 본문 텍스트 (body 토큰, 최대 4줄   │  ← 텍스트 블록
│  표시 후 "더 보기" 링크)                   │
│                                             │
├─────────────────────────────────────────────┤
│ ┌──────┐  플레이리스트 제목 (h3)            │
│ │ 커버 │  @handle의 자산 · 트랙 12개       │  ← AssetCard 임베드
│ │ 64px │  감정 태그: #비오는날 #퇴근길      │  (surface-2, radius 14px)
│ │      │  [Spotify에서 열기] [Apple Music]  │
│ └──────┘                                    │
├─────────────────────────────────────────────┤
│  ♡ 24   💬 8   ↗ 공유   🔖 저장            │  ← 액션 행 (text-mid)
└─────────────────────────────────────────────┘
```

**상세 규격:**

| 요소 | 규격 | Nocturne 토큰 |
|:---|:---|:---|
| 카드 배경 | surface-1, radius 18px, hairline 보더 | `bg-surface-1 border-hairline` |
| 작성자 아바타 | 32px 원형, 링 없음 | 이미지 radius 999px |
| 작성자명 | sm 600, text-hi | |
| 핸들 | sm, text-mid | |
| 시간 | sm, text-low | |
| 본문 텍스트 | body 400, text, line 1.6 | 최대 4줄 → "더 보기" |
| AssetCard 임베드 | surface-2, radius 14px, 커버 64px | |
| 커버 이미지 | 64px 정사각, radius 10px, 글로우 경량 | |
| 자산 제목 | h3 600, text-hi | |
| 자산 부제 | sm, text-mid | |
| 감정 태그 | label, accent-soft bg, accent text, radius 999px | `EmotionTagPicker` |
| "열기" 버튼 | ghost, sm, text-mid → 외부 딥링크 | |
| 액션 행 | sm, text-mid, 간격 24px | |
| ♡ 좋아요 | 탭 시 accent로 채워짐, 카운트 num 토큰 | |
| 💬 댓글 | 탭 시 댓글 입력창 슬라이드업 | |

```
┌──────┐  트랙 제목 (h3)
│ 커버 │  아티스트 · 앨범

```

## 3. 벤치마크 C — 감성 선물

### 3.1 카카오톡 선물하기

**핵심 패턴:** 상품 선택 → 메시지 카드 작성 → 배송지 없이 링크 전송 → 수신자가 수락/거절 → 포장 이미지 애니메이션 "언박싱".

**차용할 것:**
- 선물 발송과 수락을 분리 — 발신자는 "포장된 상태"로 보내고, 수신자는 수락 시점에 언박싱 연출 경험
- 메시지 카드 작성 단계 — 플레이리스트 선물에서 "왜 이 음악을 보내는지" 편지 한 줄 강제 유도 (선택)
- 수신자가 거절 가능한 옵션 — 강요 없는 선물 경험

**피할 것:**
- 결제/포인트 교환 단계 — plshare2 선물은 감성 교환이지 상거래가 아님 (MVP)
- 선물 "카탈로그" 구조 — 자산은 사용자가 직접 만든 것이지 상품 목록이 아님

---

### 3.2 Spotify Wrapped 공유 카드

**핵심 패턴:** 연간 리스닝 데이터를 세로형 스토리 카드로 시각화. 배경은 앨범아트 팔레트 추출 그라디언트. 공유 버튼으로 인스타그램/트위터로 즉시 이동.

**차용할 것:**
- 앨범아트 팔레트 추출 배경 — Nocturne의 cover-glow 원칙과 정확히 일치. 선물 카드 배경도 같은 방식으로
- 세로형 카드 (9:16) — 모바일에서 스크린숏 + 공유에 최적. 선물 카드를 9:16 기본값으로
- 최소한의 텍스트, 최대한의 이미지 비중 — 감성 > 정보

**피할 것:**
- 연간 집계 데이터 의존 — plshare2 선물은 사용자가 원하는 시점에 발송
- 고정된 스토리 슬라이드 포맷 — plshare2 선물 카드는 편지 텍스트 분량에 따라 유동적

---

### 3.3 손편지/언박싱 메타포 설계 적용

플레이리스트 선물은 "봉투 → 카드 꺼내기 → 내용 읽기 → 음악 열기"의 오프라인 메타포를 따른다.

**선물 발신 플로우 (설계안):**

```
① 자산 선택 (내 라이브러리에서 또는 신규 변환)
② 선물 포장 선택 (Nocturne 스킨 3종: 기본 Ink / 따뜻한 Amber / 차가운 Indigo)
③ 편지 카드 작성 (선택, 최대 200자)
④ 수신자 지정 (앱 내 @handle 검색 또는 링크 공유)
⑤ 발송 → /gift/[token] URL 생성
```

**선물 수신 플로우 (설계안):**

```
① 알림 도착 또는 링크 클릭
② /gift/[token] — 봉투 이미지 화면 (발신자명 + "당신에게 선물이 도착했어요")
   → "열어보기" 버튼 (accent, 펄스 글로우)
③ 언박싱 애니메이션 — 봉투가 열리며 앨범아트 슬라이드업 (spring 모션, 400ms)
   → 편지 텍스트 fade-in
   → 트랙 리스트 순차 등장 (stagger 60ms)
④ 수락/거절 선택
   - 수락: "내 라이브러리에 저장" → /assets/[id] 로 라우팅
   - 나중에: 토스트 "언제든 다시 열 수 있어요" (링크 유효 기간 표시)
   - 거절: 발신자에게 알림 없이 조용히 처리
```

---

### 3.4 선물 포장 스킨 (Nocturne 컬러 내 설계)

| 스킨명 | 배경 처리 | 봉투 보더 | 언박싱 포인트 |
|:---|:---|:---|:---|
| Ink (기본) | cover-glow + 딥다크 | hairline-strong | accent indigo 리본 |
| Amber | 앨범아트 warm tint overlay | warning 톤 hairline | warning 리본 |
| Indigo | accent-soft radial fill | accent 보더 | accent-hi 글로우 |

새 테마 생성 없이 Nocturne 기존 토큰 조합으로 처리한다.

## 4. 벤치마크 D — 랭킹

### 4.1 Spotify Charts

**핵심 패턴:** 국가/글로벌 차트를 순위+트랙명+스트리밍 수 테이블로 나열. 주간/일간 토글.

**차용할 것:**
- 순위 변동 인디케이터 (↑3, ↓1, NEW) — 시선을 끄는 동적 요소
- 기간 필터 (이번 주 / 지난 주) — 랭킹의 시간 차원

**피할 것:**
- 스트리밍 수 기반 순위 — plshare2는 스트리밍 카운트가 없음. 대신 저장/공유/선물 횟수 기반
- 트랙 단위 랭킹 — plshare2 랭킹 단위는 Playlist Asset
- 테이블 레이아웃 — 발견 피드 목표와 정반대

---

### 4.2 Melon Top100

**핵심 패턴:** 1~100위 수직 리스트, 각 항목에 앨범아트+순위+곡명+아티스트+재생수. 상단 배너에 1위 트랙 강조.

**차용할 것:**
- 상단 히어로 강조 — 1위 자산을 큰 AssetCard로 전면 배치
- 순위 숫자를 대형 num 토큰으로 — 숫자 자체가 비주얼 요소가 됨

**피할 것:**
- 100개 아이템 수직 스크롤 — 모바일에서 피로. plshare2는 Top 20 + "더 보기" 페이지네이션
- 재생 수 기반 지표 노출 — plshare2와 무관한 지표

---

### 4.3 Product Hunt — 투표 기반 발견

**핵심 패턴:** 오늘의 제품 리스트, upvote 버튼, 트렌딩 섹션, 카테고리 필터. "발견" 자체가 경험의 목적.

**차용할 것:**
- **Upvote 인터랙션** — 좋아요보다 "이거 진짜 좋다"는 능동적 추천 제스처. plshare2 랭킹 지표로 채택
- 카테고리/태그 기반 필터 — 감정 태그(#비오는날, #집중)로 랭킹 필터링
- 시간 범위 필터 (오늘 / 이번 주 / 이번 달) — 신선도 있는 랭킹

**피할 것:**
- 헌터/메이커 구분 — plshare2에서는 모든 사용자가 동등한 자산 작성자
- 댓글이 별도 페이지 — plshare2는 피드 카드 내 인라인 댓글

---

### 4.4 왓챠피디아 — 취향 발견

**핵심 패턴:** 평점 분포, 비슷한 취향 사용자 추천, "나라면 좋아할까?" 친밀감 언어.

**차용할 것:**
- **취향 기반 발견 언어** — "이걸 좋아한 사람이 좋아한 자산" 텍스트 레이블. 알고리즘 배경 없이도 감성 언어로 발견 동기 부여
- 평가보다 기록 우선 — 별점 없이 "저장/공유/선물"한 횟수로 취향 신호 집계
- 취향 매칭 단서를 감정 태그로 — "퇴근길 자산 12개" 같은 태그 집계 표시

**피할 것:**
- 별점/숫자 평가 시스템 — plshare2는 평점이 아닌 공감(좋아요+저장+선물) 기반
- 상세한 리뷰 텍스트 — 자산 자체의 일기가 리뷰 역할을 함

---

### 4.5 랭킹 → 발견 피드 전환 패턴 권고

랭킹을 "차트"가 아닌 "발견 피드"처럼 느껴지게 하기 위한 3가지 원칙:

**1. 순위 숫자를 장식으로, 자산을 주인공으로**
- 숫자는 대형 num 토큰 + text-low 컬러로 배경에 위치
- 앨범아트(cover-glow 포함)가 카드 면적의 60% 이상 차지
- 자산 제목, 작성자 @handle, 감정 태그가 순위보다 시각적 우선

**2. 감정 태그 필터로 개인화된 차트**
- 전체 랭킹 대신 "지금 나의 #퇴근길 랭킹" 같은 필터링된 뷰
- 감정 태그를 수평 스크롤 칩으로 제공, 선택 시 랭킹 실시간 갱신

**3. 랭킹에서 즉시 변환/저장으로**
- 각 랭킹 카드에 "내 라이브러리에 저장" + "이걸로 변환" CTA 내포
- 발견 → 소유 → 변환의 3단계를 한 화면에서 처리

### 5.3 Nocturne 일관성 체크

신규 소셜 컴포넌트는 모두 기존 Nocturne 토큰으로 처리 가능하다.
- 새 색상 도입 없음 (Amber 스킨은 `--warning` 토큰 재활용)
- 새 타이포 토큰 없음 (기존 h3/body/sm/label/num 활용)
- 새 모션 패턴 없음 (기존 spring fade+rise + stagger)
- 유일 신규 컴포넌트: `GiftCard`, `GiftEnvelope`, `RankingCard` — 기존 `AssetCard` 베리에이션으로 구현 가능
